# VisionQA UI 原型设计 Brief v0.1

> 状态：待创意总监确认  
> 范围：产品工作台原型，不含营销官网，不进入正式前端开发  
> 参考：Apple 官网的精确与克制；用户提供的黑白建筑、咖啡产品页面参考

## 1. Design Read

这是一个供服饰电商视觉审核人员长时间使用的桌面端产品工作台。设计语言应像一个安静、专业的视觉编辑室：浅色环境、图片主导、结构明确、几乎没有装饰性色彩，审美来自比例、留白、裁切、字体和内容秩序，而不是渐变、玻璃或“AI 科技感”。

设计参数：

```text
DESIGN_VARIANCE: 6
MOTION_INTENSITY: 3
VISUAL_DENSITY: 6
COLOR_STRATEGY: Restrained
PRIMARY_THEME: Light
```

## 2. 设计目标

- 用户在一个批次中快速完成图片分流与人工复核；
- 图片和问题证据始终是视觉主角；
- `PASS / REVIEW / REJECT` 清晰但不靠大面积红绿灯染色；
- 让系统判断看起来可追溯，而不是神秘的 AI 分数；
- 同时传达审美专业度与企业工具可信度；
- 验证期所有系统 `PASS` 仍需 100% 人工复核。

## 3. 视觉方向

### 3.1 从参考图保留

- 黑白为主，允许极少量状态色；
- 画面或商品图承担最大视觉重量；
- 非对称布局与宽松留白；
- 黑色块用于结构分区，不用于制造“暗黑科技”；
- 大图、细线、小字号辅助信息形成比例反差；
- 界面边界干净，阴影非常克制。

### 3.2 不照搬

- 不把营销页的大标题比例直接带入审核工作台；
- 不使用大面积悬浮产品图作为功能装饰；
- 不用巨型圆角、玻璃拟态、紫蓝渐变；
- 不把所有信息装进等尺寸卡片；
- 不为了“像 Apple”隐藏重要状态或降低信息密度。

## 4. 色彩与材质

初始建议：

```text
Canvas:       中性浅灰白
Primary Ink:  接近纯黑
Surface:      纯白
Divider:      中性浅灰
Selected:     黑色 / 反白
PASS:         低饱和深绿，仅用于点和文字
REVIEW:       低饱和琥珀，仅用于点和文字
REJECT:       低饱和深红，仅用于点和文字
Focus:        单一冷蓝，仅用于键盘焦点和链接
```

商品图周围使用中性背景，避免界面色温影响对服饰颜色的判断。

## 5. 字体与图形

- 产品界面使用一套高可读无衬线字体；
- 数字、版本和技术信息可用同字体的 Mono 分支；
- 标题不追求营销页式巨大字号；
- 图标统一使用一套细线图标，不手绘 SVG；
- 品牌尚未命名，原型仅使用 `VisionQA` 内部代号；
- 状态除了颜色还必须配文字和形状，避免只靠颜色表达。

## 6. 核心页面范围

### Screen A：项目与批次列表

目标：快速判断哪些批次需要处理、卡在哪里、完成了多少。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ VisionQA                批次 / 标准 / 评测                 [新建批次] │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│ 批次                                                    搜索  筛选   │
│ 24 个批次 · 3 个等待人工复核                                          │
│                                                                     │
│ ┌───────────────┐  夏季连衣裙 · 0728                       REVIEW  │
│ │  4张图片拼贴   │  128 张 · PASS 46 / REVIEW 17 / REJECT 65       │
│ └───────────────┘  商品参考缺失 3 · 上次运行 14:32                  │
│ ─────────────────────────────────────────────────────────────────── │
│ ┌───────────────┐  针织上装 · 0727                         RUNNING │
│ │  4张图片拼贴   │  84 / 200 已完成 · 预计剩余 08:14                 │
│ └───────────────┘  [与最终布局同形的进度骨架]                         │
│ ─────────────────────────────────────────────────────────────────── │
│ 空状态：建立第一个审核批次，并先说明需要候选图和商品参考图。             │
└─────────────────────────────────────────────────────────────────────┘
```

布局原则：不用卡片墙；使用图片预览、分隔线和清晰行结构。

### Screen B：批次审核工作台

目标：在保持上下文的情况下快速浏览、筛选和复核图片。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ ← 夏季连衣裙 · 0728   128 张      [全部] [PASS] [REVIEW] [REJECT]       │
├───────────────┬──────────────────────────────────────┬───────────────────┤
│ 筛选           │                                      │ 当前素材           │
│               │   ┌────────┐ ┌────────┐ ┌────────┐   │ REVIEW            │
│ 系统状态       │   │ 商品图  │ │ 商品图  │ │ 商品图  │   │ 2 Major           │
│ 问题类型       │   └────────┘ └────────┘ └────────┘   │                   │
│ 是否人工复核   │   ┌────────┐ ┌────────┐ ┌────────┐   │ · 袖口结构疑似错位  │
│ 参考材料状态   │   │ 商品图  │ │ [选中] │ │ 商品图  │   │ · 右手抓握不自然    │
│               │   └────────┘ └────────┘ └────────┘   │                   │
│               │                                      │ [打开证据详情]     │
│               │   支持图片尺寸切换与键盘快速选择        │ [确认] [改判]       │
├───────────────┴──────────────────────────────────────┴───────────────────┤
│ 已人工复核 36 / 128 · 验证期 PASS 仍需 100% 人工复核                     │
└──────────────────────────────────────────────────────────────────────────┘
```

布局原则：三栏但不平均。图片网格占最大面积；筛选栏最窄；当前判断栏保持稳定宽度。

### Screen C：单图证据详情

目标：理解系统为什么这样判断，并完成可信的人工裁决。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ ← 返回批次       048 / 128                           REVIEW · 置信度待定 │
├─────────────────────────────────────────────┬────────────────────────────┤
│                                             │ 商品参考                    │
│                                             │ [正面] [背面] [细节]        │
│              候选大图                        ├────────────────────────────┤
│                                             │ 发现 2 个问题               │
│       [证据区域框只在选中问题时出现]           │                            │
│                                             │ 01 袖口结构疑似错位 · Major │
│                                             │ 可观察事实 / 影响 / 依据     │
│                                             │                            │
│                                             │ 02 右手抓握不自然 · Major   │
├─────────────────────────────────────────────┴────────────────────────────┤
│ [上一张] [下一张]       [确认 REVIEW] [改为 PASS] [改为 REJECT]           │
└──────────────────────────────────────────────────────────────────────────┘
```

布局原则：大图不放在卡片里；问题列表与证据区域联动；参考图是核验依据，不是装饰缩略图。

### Screen D：人工改判与返工复审

目标：留下可以成为未来数据资产的改判原因，而不是只改一个状态。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 将 REVIEW 改为 REJECT                                                │
├─────────────────────────────────────────────────────────────────────┤
│ 改判原因                                                             │
│ ○ 系统漏掉阻断问题  ○ 严重度判断错误  ○ 商品规则不适用  ○ 其他          │
│                                                                     │
│ 关联问题    [PF-03 袖口结构错误]                                      │
│ 业务证据    [填写具体商品结构与参考依据，不接受“感觉不对”]                │
│ 返工动作    [重新生成 / 局部修图 / 补充参考材料 / 不再使用]               │
│                                                                     │
│                                           [取消] [保存改判并进入下一张] │
└─────────────────────────────────────────────────────────────────────┘
```

布局原则：优先使用侧边工作区或内联面板，避免把关键判断塞进小型模态框。

## 7. 交互模型

- 图片网格支持键盘方向键移动；
- `1 / 2 / 3` 可映射为 PASS / REVIEW / REJECT，但首次使用需提示；
- 选择问题时，大图显示对应证据区域；
- 人工改判必须填写原因码，关键改判必须补业务证据；
- 修改输入、参考图或规则版本后产生新运行，不覆盖旧结果；
- 状态切换使用 150–250ms 过渡，只表达选择和面板变化；
- 支持减少动态效果；
- 不使用装饰性入场动画。

## 8. 必须设计的状态

- 首次使用与空批次；
- 批次上传与解析中；
- 运行中与部分失败；
- 图片损坏或不可读取；
- 缺少商品参考图；
- 模型返回无效结构；
- PASS / REVIEW / REJECT；
- 系统判断与人工改判不一致；
- 返工后等待复审；
- 批次全部完成；
- 网络中断后的可恢复状态。

## 9. 原型范围

第一轮原型：

- 桌面端四屏；
- 中等保真；
- 使用模拟服饰占位图，不使用客户素材；
- 展示默认、选择、REVIEW、证据详情和改判状态；
- 暂不实现后端和真实模型；
- 暂不做营销官网；
- 暂不确定品牌 Logo 和最终产品名。

## 11. 确认门禁

在正式原型代码开始前，需要创意总监确认：

- 浅色、黑白、图片主导的方向是否正确；
- 四屏核心范围是否正确；
- “审美来自比例与内容秩序，而不是装饰效果”是否符合产品气质。
