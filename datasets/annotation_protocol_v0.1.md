# 服饰电商 AI 模特商品图标注协议 v0.1

> 状态：模拟演练版，待真实客户素材验证  
> 依据：`standards/taxonomy_v0.1.md`、`standards/gates_v0.1.md`、`contracts/evaluation-result.schema.json`  
> 限制：当前没有真实客户图片、品牌规范和线上返工结果。本协议中的阈值、样本量和裁决规则均待验证。

## 1. 目标与边界

本协议用于建立可复现的人工基准标签，验证模型观察层与确定性规则层。标注者不评价图片是否“有高级感”，而是记录可见事实、影响、严重度和证据。

标注分为两层：

1. **观察层**：人工识别 issue code、类别、严重度、状态、区域、事实和影响。
2. **规则层**：依据版本化门禁生成 `PASS / REVIEW / REJECT`；不得用总分抵消 Blocker。

模拟 case 只能检查协议、字段和规则流程，不得用于报告真实准确率、模型质量或商业可用性。

## 2. 角色

- 标注员 A：独立标注，不查看 B 的结果。
- 标注员 B：独立标注，不查看 A 的结果。
- 裁决员 C：仅在 A/B 提交并锁定后查看分歧；应由创意总监或经校准的高级审核员担任。
- 数据管理员：分配匿名 case、冻结版本、检查 schema、记录变更，不参与标签裁决。

同一人不得同时担任某 case 的独立标注员与裁决员。

## 3. 标注前输入检查

每个真实 case 应至少包含：

- 候选图片；
- 商品标准图，建议包含正面、背面和关键细节；
- SKU 不可改变项：品类、颜色、版型、图案、Logo、结构件；
- 目标渠道、版位与尺寸；
- 品牌视觉规范；
- 合规适用平台和地区；
- 授权状态或待法务确认项。

缺失材料必须记录在 `scope`：

- `VERIFIED`：权威材料齐全且已核验；
- `LIMITED`：有部分材料，只能有限判断；
- `NOT_VERIFIED`：没有足够证据；
- `NOT_APPLICABLE`：该项不适用。

缺少商品参考时不得把 `product_fidelity` 标为通过，应产生 `AS-04` 或限定评估范围。

## 4. 独立标注步骤

每位标注员按以下顺序完成：

1. 检查可评估性，先标 `AS-*`。
2. 对照参考资料检查商品忠实度 `PF-*`。
3. 检查人体完整性 `HI-*`。
4. 检查服装与材质 `GM-*`。
5. 检查摄影物理 `PP-*`。
6. 检查构图与商业表达 `CC-*`。
7. 检查文字与 Logo `TL-*`。
8. 检查合规 `CO-*`。
9. 为每条问题填写可观察事实、影响、区域与证据。
10. 完成后锁定，不得在查看另一位标注结果后静默修改。

禁止使用“看着假”“不高级”“不好看”等不可复核描述。应写成如“参考图为单个翻盖口袋，候选图口袋缺失”。

## 5. 单条标签要求

字段应与 `evaluation-result.schema.json` 的 observation 对齐：

- `observation_id`：case 内唯一；
- `issue_code`：必须存在于 taxonomy v0.1；
- `category`：必须与代码前缀匹配；
- `severity`：`blocker / major / minor / information_insufficient`；
- `status`：`detected / suspected / not_assessable`；
- `region`：标明资产、坐标空间和区域名称；
- `observation`：只描述可观察事实；
- `impact`：描述对商品理解、可信度、发布或合规的影响；
- `confidence`：仅记录标注员主观确定程度，自动门槛待验证；
- `evidence_refs`：至少一项。

同一现象只设一个主类别；其他影响放入 `related_categories`。

## 6. 分歧定义

以下任一项不同即记为分歧：

- 是否存在某问题；
- issue code 不同；
- 主类别不同；
- 严重度不同；
- `detected / suspected / not_assessable` 不同；
- 门禁结果不同；
- 最终 `PASS / REVIEW / REJECT` 不同；
- scope 状态不同。

仅措辞或区域框存在小幅差异、但不影响问题身份与决策时，可记为表达差异，不进入核心一致性统计。

## 7. 分歧裁决

1. 数据管理员自动生成分歧清单。
2. A/B 各自写一句依据，不允许先协商改标签。
3. 裁决员 C 仅基于图片、参考材料、taxonomy 和 gates 判定。
4. C 可选择 A、选择 B、给出第三标签或标记“标准不足”。
5. 若标准不足，case 暂定 `REVIEW`，并创建 rubric 变更建议；不得为追求一致率强行裁决。
6. 裁决结果成为 gold label，并保存 A、B 原始标签和裁决理由。
7. taxonomy 或 gates 变更后，受影响 case 必须重新裁决并升级数据集版本。

涉及法律、平台政策或授权的分歧只能进入专业复核，不由视觉裁决员给出法律结论。

## 8. 质量控制

- 标注员先用不进入正式测试集的校准集练习；
- 校准完成后才进入正式独立标注；
- 每批混入重复 case，检查标注员自身稳定性；
- 不向标注员透露模型结果、预期类别或样本来源；
- test 集在提示词和门禁冻结后才解封；
- 所有资产按哈希去重，近似变体不得跨训练/开发/测试切分；
- 同一 SKU、同一生成批次和同一人物身份应按组切分，防止泄漏。

校准通过标准、复标比例和允许分歧率均待真实客户素材验证。

## 9. 数据版本与审计

每条正式记录应关联：

- `dataset_version`
- `taxonomy_version`
- `gates_version`
- `annotation_protocol_version`
- 匿名标注员 ID
- 标注与裁决时间
- 输入资产 SHA-256
- 参考资产 ID
- 原始标签、裁决标签和裁决理由

不能覆盖历史标签；更正时创建新版本并保留变更记录。

## 10. 当前模拟集的用途

`simulation_manifest_v0.1.jsonl` 的 12 条记录：

- 没有真实图片；
- 只用于检查 8 类 taxonomy 覆盖、门禁逻辑、JSONL 解析和测试代码；
- 不参与训练、调参、准确率、κ、召回率或 Go/No-Go 的数值计算；
- 后续必须由真实客户或经授权的近似业务素材替换。
