# VisionQA Discovery Pilot v0.2

状态：`READY_FOR_INTERNAL_EXECUTION`  
外部审查门：`GO_FOR_DISCOVERY`  
生成日期：2026-07-31

## 本轮唯一目标

用最小成本验证：服饰品牌或内容服务商是否愿意为“AI 商品图发布前审核、风险解释与返工闭环”付费。

本轮不增加产品功能，不训练模型，不上传或复制客户原图，不使用校准集或评估留出集。

## 团队与验收

| 角色 | 职责 | 输入 | 独立输出 | 验收标准 |
|---|---|---|---|---|
| 联合创始人兼 CTO / 主 Agent | 承接外审结论、控制范围、形成执行闭环 | 外审 CSV、MVP、资产清单 | 本目录全部执行资产 | 9 项外审均有行动；没有虚构客户证据；功能范围不扩大 |
| Customer Discovery Agent | 找到真实痛点、替代方案与付费意愿 | 访谈脚本、目标账户池 | 获客节奏、访谈与报价标准 | 12 次有效访谈、6 次产品演示、3 份同口径报价、1 笔真实付款 |
| MVP Closure Engineer | 建立受控样本和可复现实测字段 | 87 张资产的只读清单 | 17 张本地试点清单、运行手册 | 仅 DEVELOPMENT_REFERENCE；原图不复制/移动/上传；每次测量可追溯 |
| Independent Release QA | 查漏项、越权和数据泄漏 | 外审决策、所有试点资产 | 独立 GO/HOLD 报告 | 逐条覆盖 ER-01 至 ER-09；任何阻断问题未关闭则 HOLD |

没有新增 Agent。上述三个子角色分别减少串行时间、产出独立资产或降低错误率。

## 文件索引

- `external_review_intake.md`：九项外审结论的执行承接。
- `controlled_pilot_manifest.csv`：17 张本地只读样本及完整测量字段。
- `target_account_pipeline.csv`：首批 5 家品牌/零售商与 5 家服务商候选池。
- `discovery_activity_log.csv`：12 次访谈、6 次演示、3 份报价、1 笔付款的证据台账。
- `priced_pilot_offer.md`：统一口径的付费试点提案。
- `outreach_messages.md`：不冒充客户、不承诺未有能力的邀约文案。
- `fourteen_day_runbook.md`：14 个工作日执行节奏、继续/停止阈值。
- `agent_review_decisions.md`：主 Agent 对子团队建议的采纳/拒绝及理由。
- `D:\VisionQA\runs\discovery_pilot_v0.2\`：实际运行空表与预检账本；本目录只做交付定义。

## 当前真实边界

- 17 张记录引用现有清单，不包含图片二进制。
- 资产当前授权范围是内部 VisionQA 评估/基准，外部传输仍需治理门批准。
- 因项目目录中没有这些图片二进制，也没有目标联系人的授权业务账号，本包没有伪造“已审核”“已访谈”或“已发送”。
- 获得客户授权后，必须在原文件所在设备上做本地演示；任何上传、邮件附件或网盘传输都需要单独批准。

## 完成定义

只有同时满足以下条件，才可宣布产品价值初步成立：

1. 至少 12 次合格访谈，其中品牌/零售商与服务商均不少于 5 次；
2. 至少 6 次使用客户授权图片的受控演示；
3. 至少 3 份相同范围、相同价格的正式报价；
4. 至少 1 笔真实到账，不能用口头“有兴趣”替代；
5. 演示数据包含上下文完整率、人工决定、返工轮次和审核耗时；
6. 没有客户资产外传或数据集污染。
