# VisionQA 视觉 AI 智能体：产品定义 v0.1

日期：2026-09-10。产品方向已获用户明确认可；以下首版范围、交互样例与验收细节为本轮提出的产品规格，不代表已实现或客户验证。

## 1. 产品主体

VisionQA 是面向视觉任务的 AI 智能体：理解目标与素材，规划并调用工具，结合反馈调整，协助用户完成可采用的视觉交付。

审核、修图、商品一致性检查是第一个业务能力包，不是产品永久边界。对话是任务入口，视觉工作区是素材、证据、版本和交付的操作载体；不能只给原工作流加聊天皮肤，也不能把全部操作藏进聊天记录。

用户的三个目标分别是展示专业能力、获得可用收入、探索视觉智能体与反馈学习。分别以真实案例、扣除人工与调用成本后的收益、可复验的学习实验衡量，不互相冒充。

## 2. 首版用户与价值假设

首版沿用服饰电商场景，服务有真实商品参考、候选图片和近期交付任务的人。邀请接收者的职业、任务频率与付款权尚待核实，不能假设他们都是商家。

核心假设：用户愿意交代目标并保留关键判断，将素材组织、问题检查、修正推进和版本管理交给智能体。需要与用户现有做法比较，而不是只统计聊天次数。

首个任务：把已有同一 SKU 的候选图检查并修正到可供用户复验的状态。保留现有 1–4 张真值、1–10 张候选的批次范围；实际执行上限以已验证能力为准。新图创作、视频、批量排版是后续能力候选，本版不承诺实现。

## 3. 工作职责

用户负责目标、必要商品事实、关键取舍、费用授权与最终采用。智能体负责整理上下文、识别信息缺口、提出可执行计划、组织工具执行、展示证据、复验与总结。

对话必须与具体任务、素材和版本关联。“这张”“刚才那版”无法唯一指向时，展示缩略图让用户选择；不得猜测并发起收费操作。

工作区持续显示：任务目标、当前动作、相关图片、等待用户决定的事项、预算/额度、交付版本。用户能回到旧版本、查看失败原因、停止后续动作。

客户看到事实性状态，例如“已检查 3/5 张”“正在修正袖口”“需要确认纽扣数量”。不伪造多个模型对话，不展示隐藏推理，不把计划或排队称作执行完成。

## 4. 自主性与批准边界

| 动作 | 首版规则 |
| --- | --- |
| 整理已授权素材、摘要现有检查结果、提出计划 | 自主执行；无证据的商品属性标为未知 |
| 对外发送素材进行筛查 | 使用已批准的数据范围、服务与预算；免费额度不等于供应商零成本 |
| 发起修正 | 展示目标图片、修改与锁定范围、额度和轮次；用户批准后执行 |
| 同一已批准动作的状态查询、恢复展示 | 不重复询问，不重复创建计费任务 |
| 用户要求下一轮修正 | 更新计划；明确本轮消耗。超出原批准轮次或范围时再次确认 |
| 新供应商、超预算、增加图片用途、公开发布、删除项目 | 不从一般聊天推定授权；按对应规则取得明确授权 |
| 修改商品事实、自动宣布商品绝对正确 | 不允许；证据冲突需用户确认，交付保留人工终审 |

模型不能自行提高额度、扩大工具权限或取消 Gate。本产品定义不变更已有费用硬停和支付关闭规则；执行真实测试前核对剩余预算。

## 5. 任务完成与停止

任务状态应区分：需要补充信息、计划待确认、执行中、待用户复验、已交付、部分完成、失败、已停止。

有效输出不等于已交付；基础 Gate 通过不等于商品正确。只有用户确认选定版本并能取得交付文件，才记录本次交付；实际用于商业素材另行记录，不以下载替代采用。

失败保留素材、目标、尝试记录及费用结果，给出明确下一步。收费请求结果未知时先核对原任务，不自动重发。用户停止后不再发起新动作；已提交外部任务可能无法撤回，应如实说明其状态与费用。

## 6. 学习边界

任务内：用用户反馈修订目标或修正策略，保留版本与原因；达到批准轮次、预算上限，或发现持续漂移时停止自动推进。

跨任务：只有取得相应用途授权的反馈才能进入研究数据。候选策略需要在保留失败案例的评测集上比较质量、漂移、成本与轮次，经过审查后更新。不得跨租户泄露素材或偏好，不由智能体直接改写线上规则。

“自我进化”是研究方向，不是当前能力声明。模型可替换；潜在长期资产是经授权的商品事实、错误证据、修正选择和采用原因关联，而非模型数量。

## 7. 首轮验证与产品取舍

用户需求：先观察独立操作，再允许协助；分别记录成功率、卡点和人工介入。商业价值：观察真实采用、再次提交和真实付款，尚无证据时保持假设。MVP：只贯通首个业务能力包，不同时扩展所有视觉业务。竞争优势：验证客户标准与反馈是否真正改善交付，不预先宣称数据壁垒。

待从体验中回答：用户是否愿意交代目标而非逐步点按钮？对哪些图片必须自己控制？为何选择本产品而不是直接使用现有修图工具？是否愿意为下一次任务支付，且人工成本可接受？

## 8. 推进顺序与退出条件

1. 产品定义与任务样例：本文件及配套样例完成；明确能力边界和未验证项。
2. 对话任务体验：先在内部展示目标、素材指向、计划确认、执行状态和版本交付；既有客户入口保持可用，不静默切换内测用户。
3. 首个能力包贯通：接入既有检查与修正流程，验证失败、重复提交、刷新恢复、停止和额度一致性。持久化及隔离能力须现场核验，不能把旧部署记录当作已达标。
4. 受控真实验证：在已授权素材与剩余预算内，从客户实际点击走到真实结果复验；示例测试与真实质量证据分开。
5. 小范围体验：观察真实使用后决定是否推广新入口；新增业务能力以具体任务需求和可交付证据为依据。

本轮不部署、不收费调用、不更改邀请码、不增加公开承诺。后续发布目标仍为用户指定的阿里云测试环境，不切换到其他托管平台。
