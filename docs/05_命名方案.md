# 项目命名方案 v0.2

## 当前结论

`准镜`与`VisualGate`均已淘汰，不作为候选名称。`VisionQA`暂时只保留为内部项目代号。

第一轮命名的问题是从“准、镜、视觉、门禁”等功能语义直接拼接，虽然容易理解，但同质化严重，而且没有先完成名称占用预检。后续改为先定义品牌性格和命名约束，再生成候选并逐个预检。

创意总监已选择下一轮采用“独立品牌型”命名。

## 1. 命名问题

不建议继续使用 `VisionOS`：

- 容易被理解为 Apple 的 visionOS 操作系统或空间计算应用；
- 无法表达“商业发布前质检”的核心价值；
- 搜索、传播和团队沟通中容易产生歧义。

`VisionQA` 可以继续作为内部技术代号，但对外偏工程化，用户不容易立刻理解价值。

## 2. 推荐的三层命名

### 内部项目代号：VisionQA

用于仓库、技术文档、API 和评测系统。暂时无需改动 `D:\VisionQA` 路径。

### 已淘汰：准镜

含义：

- “准”代表准确、标准和发布准入；
- “镜”代表视觉、审视和成像；
- 两个字简洁，适合中文产品；
- 可延展为“准镜评分”“准镜报告”“准镜标准库”。

建议说明语：

> 准镜——AI 商业视觉发布前质检。

已淘汰的英文工作名：

> VisualGate

含义是视觉内容进入发布流程前的质量门禁，适合 API 和 B2B 产品表达。

### 核心技术资产名：Visual Quality Standard Library

中文：

> 商业视觉质量标准库

避免将核心资产只称为 Prompt 或 Skill，突出它包含规则、案例、标注和回归评测。

## 3. 已淘汰或暂不采用的名称

| 名称 | 气质 | 优点 | 风险 |
|---|---|---|---|
| 准镜 | 专业、克制 | 中文简洁，兼顾标准与视觉 | 已有相关使用，淘汰 |
| 视准 | 技术、平台 | 直接表达视觉标准 | 发音和品牌感稍弱 |
| 质镜 | 品质、审视 | 接近质量审核含义 | “质”字略偏传统质检 |
| 图鉴官 | 亲和、Agent 化 | 适合创作者端 | B2B 专业感较弱 |
| 视觉门 | 基础设施 | 强调发布门禁 | 中文品牌感一般 |
| VisualGate | B2B、技术 | 清楚表达视觉准入层 | 已有海外视觉相关主体，淘汰 |
| PublishReady | 结果导向 | 直接表达“可发布” | 不只限定视觉，范围较宽 |
| PixelProof | 创意、国际化 | 有视觉检测感 | 容易被理解为像素或版权工具 |

## 4. 下一轮命名流程

下一轮候选必须按以下顺序产生：

1. 明确品牌更偏“专业基础设施”还是“有审美人格的创意伙伴”；
2. 避免直接使用“镜、视、图、AI、质检”的常见二字拼接；
3. 生成三条不同方向的候选，而不是同一词根变体；
4. 检索企业名、软件产品、商标、域名、应用商店和社交平台；
5. 通过预检后才进入视觉设计和传播测试。
