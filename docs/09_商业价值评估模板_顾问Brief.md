# VisionQA · 商业价值维度重构 — 开发 Brief（给 Codex）

> 用途：指导原型第四维（商业价值，权重 35%）从「绝对分」重构为「可配置评估模板 + 客户校准飞轮」。
> 视角：产品负责人 / 投资人。本文只定义**要做什么、怎么建模、怎么验收**，不含实现代码。
> 阶段：仍属 Phase 1 验证期，暂不接真实模型。

---

## 0. 一句话目标

商业价值不是「模型觉得这张图美不美」，而是「这张图符不符合**这个甲方的具体标准**」。
把第四维从绝对评分，改成**模板化相对评估 + 客户校准数据回流**。

---

## 1. 背景与要解决的问题

当前原型（`D:\VisionQA\web`，Codex 已建）第四维是一个绝对分：

```
商业价值诊断  68 / 100
```

问题：
- 商业价值（点击欲望 / 品牌感 / 卖点表达）**本质是主观偏好**，不是客观缺陷。
- 模型会用它自己的「通用好看偏见」来评，这和甲方品牌标准必然冲突。
- 冲突时「谁校准谁」没定义 → 该维度一旦被甲方质疑，整层评估的可信度会塌。

同类风险：前三维（真人 / 摄影 / 材质）是客观缺陷检测，最容易被上游平台（MJ / SD / Claude 自带质量分）吞掉。商业价值维度若也做成通用绝对分，同样会被吞。**只有「绑定客户标准的相对评估」是平台方抄不走的。**

---

## 2. 已确认的产品决策

1. **护城河公式**：护城河 = 审美判断标准（输入）× 客户校准数据飞轮（放大器）。
   - 规则库（PF-03 / HI-04 / MAT-03）可抄；审美可学；但「成千上万个甲方口味模型」抄不走。
2. **第四维形态 = 可配置评估模板（template）**，而非单一通用分。
3. **修复 Prompt 定位**：是付费意愿探针，不是核心竞争力。本 brief 不展开。
4. **不做改图工具**：闭环止于「评估 + 优化前后对比」，生产层交给用户既有工作流。

---

## 3. 第四维重构要求（给开发者的需求）

### 3.1 模板化（内置场景模板）
内置若干预设模板，每模板一套权重 + 判据（非硬编码绝对分）：
- 预售白牌（强调：卖点表达、价格感、信息清晰度）
- 大牌旗舰（强调：品牌感、高级感、留白与质感）
- 直播带货（强调：主体突出、点击欲望、促销氛围）
- 站酷 / 设计风（强调：创意、构图、情绪表达）

### 3.2 客户自定义模板
- 客户可上传：**brief / 品牌指南 / 历史爆款图**（作为参照系）。
- 模型输出从「我打 68 分」变为「相对您品牌调性：主体权重不足、情绪偏冷」。
- 判分输入改为「该模板的判据」，不再用模型通用审美。

### 3.3 输出形态变化
- 旧：`商业价值 68/100`（绝对）
- 新：`相对模板「大牌旗舰」贴合度：中（主体权重不足 / 情绪偏冷）` + 可量化子项

### 3.4 校准回流（飞轮起点）
- 客户每次在 human-in-the-loop 里**改判** → 写入该客户的 `commercial_profile`。
- 后续同客户评估优先用其 `commercial_profile` 而非通用模板。
- 这是数据飞轮的燃料（详见第 5 节），当前 Phase 1 只需把**采集与写入通道**设计出来，不要求真训练。

---

## 5. 数据飞轮（概念定义，Phase 1 仅设计口径）

- **种子**：产品方自标 100+100 张 A/B/C（Day 2–3，策划书原有计划）。
- **雪球**：客户在验证期每次改判 → 回流校准其 `commercial_profile`。
- **闭环**：客户用得越久 → 你越懂他家的「能发 / 不能发」→ 迁移成本越高 → 壁垒越深。
- **当前状态**：飞轮尚未建立，本 brief 要求先把「改判 → 写回」的通道在原型里留好（哪怕先存本地 / 弹 toast 占位），不要等到接模型才想。

---

## 6. 验收标准（产品视角，非代码标准）

1. 用户能**选择 / 新建**一个商业价值模板。
2. **同一张图**在「大牌旗舰」与「直播带货」模板下，商业价值结论可不同（证明不是绝对分）。
3. 客户一次改判后，**后续同客户**的评估能体现该改判影响（飞轮通道通）。
4. 第四维结论以「相对模板的贴合度 + 子项」呈现，不再出现裸绝对分。

---

## 7. 明确不在本次范围

- 不接真实多模态模型（仍 Phase 1 验证）。
- 不做改图 / 生产工具。
- 不要求真实训练 `commercial_profile`，只要求通道与结构就位。

---

## 8. 给开发者的备注

- 本 brief 是从产品 / 投资人视角写的，目的是让你改原型第四维时有清晰的「为什么」和「改成什么样」。
- 如果你发现某条需求在当前架构下成本过高，先反馈，不要自行降级成「还是给绝对分」——那会回到被平台吞掉的陷阱。
- 界面风格维持现有浅色专业风（DESIGN.md 已定），不要引入暗色 / 玻璃拟态。
