# 第一周离线技术验证计划 v0.1

> 状态：内部草案，待真实客户素材验证  
> 适用场景：服饰电商 AI 模特商品图发布前质检  
> 依赖标准：`standards/taxonomy_v0.1.md`、`standards/gates_v0.1.md`  
> 核心原则：模型只产出可追溯的视觉观察；规则引擎依据版本化门禁生成发布决策。

## 1. 本周验证目标

本周不验证完整网站、用户系统、批量队列或商业化能力。只验证以下闭环：

```text
数据集清单
  → 输入与参考材料校验
  → Provider-neutral 模型适配器
  → 结构化观察
  → JSON Schema 校验
  → 确定性门禁规则
  → PASS / REVIEW / REJECT
  → 指标与错误分析报告
```

本周成功不等于模型已可自动发布。成功仅表示：

1. 同一输入、配置和版本能够被追溯；
2. 模型观察与规则决策被明确分离；
3. 技术失败不会被误写成质量结论；
4. 可用试标数据计算初步一致性、漏检、误放、成本和延迟；
5. 所有未被真实数据验证的阈值保持“待验证”。

## 2. 最小架构与职责边界

### 2.1 数据集清单

数据集使用不可变 manifest 描述，每个候选图至少记录：

- `asset_id`；
- 文件相对路径或受控对象存储引用；
- `sha256`；
- 场景；
- 参考商品图 ID；
- 素材授权状态；
- 数据集版本与 split；
- 标签版本。

原图和标签不得原地覆盖。修订应生成新数据集或标签版本。

### 2.2 输入校验

模型调用前先进行确定性校验：

- 文件存在、可读取、可解码；
- MIME 类型、像素尺寸与文件哈希可记录；
- 参考图和候选图对应关系明确；
- 商品信息、品牌规范、渠道要求与合规规则是否提供。

输入不足应反映到 `scope`，而不是让模型猜测。

### 2.3 模型适配器

适配器只负责：

- 把统一请求转换为供应方请求；
- 调用具备图像理解和结构化输出能力的模型；
- 保存供应方返回的模型标识、原始响应、成本与延迟；
- 将结果解析为 `model_evaluation.observations`；
- 对超时、供应方错误和无效输出返回明确失败状态。

业务层不得依赖具体供应方字段。替换供应方时不应修改 taxonomy、门禁或结果契约。

### 2.4 模型观察层

模型可以输出：

- taxonomy 中存在的 `issue_code`；
- 类别、严重度建议和检测状态；
- 证据区域；
- 可观察事实；
- 影响；
- 置信度；
- 证据引用和关联类别。

模型不得输出或决定：

- `PASS / REVIEW / REJECT`；
- Major 或 Minor 的聚合阈值；
- 0–100 总分权重；
- 法律保证；
- 未提供参考资料时的商品忠实结论。

### 2.5 Schema 校验

模型输出必须通过 `contracts/evaluation-result.schema.json` 对应的观察结构校验后才能进入规则引擎。

解析失败不得静默重试到“看似成功”。每次尝试都记录：

- 尝试次数；
- 错误类型；
- 原始响应引用；
- 耗时；
- 成本；
- 最终状态。

自动重试次数与退避策略待实际供应方错误数据验证。

### 2.6 确定性规则引擎

规则引擎读取：

- 已验证的结构化观察；
- `scope`；
- `gates_version`；
- 版本化规则配置。

规则引擎输出：

- 门禁命中；
- `PASS / REVIEW / REJECT` 或无法运行；
- 决策理由；
- 需要人工检查的项目；
- 可选软评分；
- 模型无关的修复动作。

任何 Blocker 不得被软评分抵消。“多个 Major”“Minor 聚集”、置信度阈值、PASS 阈值与自动抽检比例在 v0.1 中均不锁死。

## 3. 结果契约

统一结果由六部分组成：

| 部分 | 目的 |
|---|---|
| `schema_version` | 结果格式版本 |
| `run` | 代码、数据、taxonomy、门禁、Prompt、适配器和模型快照 |
| `input` | 候选素材、哈希、场景与参考素材 |
| `scope` | 本次实际覆盖和未覆盖的核验范围 |
| `model_evaluation` | 模型观察、警告、原始响应引用与失败状态 |
| `rule_evaluation` | 规则引擎门禁、决策、人工检查和建议 |
| `performance` | 延迟、尝试次数和成本 |

`overall_score` 在权重与映射完成真实数据标定前必须为 `null`。

## 4. 失败状态

### 4.1 模型层

| 状态 | 含义 | 规则层处理 |
|---|---|---|
| `SUCCEEDED` | 结构化观察有效 | 可运行规则 |
| `NOT_RUN` | 未发起调用 | 不运行规则 |
| `INSUFFICIENT_INPUT` | 调用所需材料不足 | 通常转人工补充材料 |
| `UNREADABLE_ASSET` | 图片不可读 | 依据可修复性进入 REVIEW 或 REJECT |
| `PROVIDER_ERROR` | 供应方失败 | 不生成视觉质量结论 |
| `TIMEOUT` | 调用超时 | 不生成视觉质量结论 |
| `INVALID_OUTPUT` | 响应不符合结构 | 不运行规则，保留原始响应 |

### 4.2 规则层

| 状态 | 含义 |
|---|---|
| `SUCCEEDED` | 规则完成 |
| `NOT_RUN` | 因模型层或流程条件未运行 |
| `INVALID_MODEL_OUTPUT` | 输入观察未通过契约 |
| `RULE_ENGINE_ERROR` | 规则配置或执行异常 |

技术失败时 `decision` 应为 `null`，不得默认成 `PASS`、`REVIEW` 或 `REJECT`。

## 5. 版本与追踪要求

每次运行必须固化：

- `run_id` 和时间；
- 代码提交或构建版本；
- dataset 与标签版本；
- taxonomy、gates 和 schema 版本；
- Prompt 版本；
- provider adapter 版本；
- 供应方返回的模型快照标识；
- 配置哈希；
- 输入文件哈希；
- 原始响应引用；
- 重试次数、错误、成本与延迟。

密钥、访问令牌、签名 URL 和个人敏感信息不得写入结果或日志。

## 6. 第一周交付物

### Day 1：契约冻结

- 评审 taxonomy 与 gates 的术语映射；
- 冻结结果 Schema v0.1；
- 准备一份成功示例与至少四份失败状态示例；
- 记录未决问题，不填造未经验证的阈值。

### Day 2：小样本与试标

- 准备 30–50 张试标素材；具体数量可随素材质量调整；
- 至少两名标注者独立标注，理想情况下三名；
- 数据包含明显问题、边界问题、正常样本和输入不足样本；
- 单独保留不用于 Prompt 调整的盲测 split。

### Day 3：离线观察链路

- 完成单图与数据集级离线调用；
- 保存输入哈希、模型观察和原始响应；
- 验证结构化解析、失败状态和可替换适配器边界；
- 不实现网页。

### Day 4：规则与回归

- 将 gates v0.1 编码为确定性配置；
- 建立最小 golden cases；
- 验证 Blocker 不被分数抵消；
- 验证缺少参考资料不会产生“商品忠实通过”；
- 验证技术失败时决策为 `null`。

### Day 5：评测报告

- 运行盲测集和重复运行；
- 输出一致性、错误类型、成本和延迟；
- 形成继续、修订或暂停的 Go / Revise / No-Go 建议；
- 只生成静态 Markdown 或 HTML 报告。

## 7. 第一周指标

当前只定义计算方法，不设上线阈值：

- A/B/C 或 PASS/REVIEW/REJECT 与人工结果的一致性；
- Blocker、Major、Minor 的分级混淆；
- 各 issue code 的召回、误报与漏报；
- `PASS` 样本中的人工返工比例（误放风险）；
- 同一图片重复运行的一致性；
- Schema 首次解析成功率与最终解析成功率；
- 技术失败率、重试率；
- 单图端到端延迟分布；
- 单图成本分布；
- 不同 scope 完整度对结果的影响。

Cohen's kappa、Fleiss' kappa、ICC 或其他统计方法应依据标注者数量和标签类型选择，不预设“达标数值”。

## 8. 第一周不做

- 完整 Web 产品、登录、权限和支付；
- PostgreSQL、复杂队列和规模化部署；
- 双模型投票或“模型多数即真值”；
- 自动发布；
- 固定 0–100 权重；
- 训练自有模型；
- 视频、3D 和多场景泛化；
- 将视觉筛查表述为法律或平台合规保证。

## 9. 本周退出条件

进入下一阶段前至少满足：

1. 示例与实际输出均可通过 JSON Schema 校验；
2. 所有结论可追溯到观察、证据、scope 和规则版本；
3. 失败状态不会产生发布结论；
4. 盲测与重复运行结果已生成；
5. 未验证阈值仍明确标记为待验证；
6. 创意总监与测试负责人共同确认下一轮要修订的 taxonomy、门禁或 Prompt。

若以上任一项不满足，应继续完善离线评测，不进入完整网站开发。
