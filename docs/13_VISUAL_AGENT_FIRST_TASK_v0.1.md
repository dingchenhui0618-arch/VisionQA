# 首个视觉智能体任务：交互样例与验收 v0.1

日期：2026-09-10。以下为设计样例，不是真实客户对话、模型运行记录或成功证据。

## 正常流程

用户上传参考图与候选图：“帮我把这组商品图检查一下，有问题的修好，衣服本身不能改。”

智能体先展示素材缩略图及用途：“这两张用作商品参考，这三张是待检查图片。”若上传角色明确则直接整理；角色不明或商品冲突时只问必要问题，不要求用户选择模型。

工作区保留任务目标与不可改动项。智能体对证据不足的属性写“无法确认”，不自行补全 Logo、纽扣数量或材质。

检查结束展示逐图证据卡，假设其中一张出现额外刺绣：“这张右胸图案与参考不一致。建议只处理该区域，保留衣服颜色、纽扣和人物构图。”此处是条件示例，实际内容必须由检查证据驱动。

用户：“修这一张。”

智能体展示选定图片、目标区域、锁定范围，以及“本轮成功返回并通过基础检查后消耗 1 次额度”。用户确认本轮计划后执行；保留现行失败释放额度规则，不作未实现的退款保证。

执行期间显示真实状态；不能只显示没有终点的“思考中”。刷新后继续展示同一任务，不因恢复页面创建新付费请求。

返回后显示原图与候选版，并说明哪些检查通过、哪些仍待人工判断。用户确认商品细节、非目标区域和整体可用性后，选择版本并下载。

用户：“这里修过头了，用上一版，保留这一块纹理。”

智能体把反馈绑定到准确版本与区域；指代不清时要求选择。恢复上一版展示不产生生成费用。下一次修正另列修改范围与额度，不自动收费重试。

## 必须可演示的异常

| 场景 | 预期行为 | 不可接受行为 |
| --- | --- | --- |
| 没有真值图 | 解释能做哪些观察，提示补参考后才能判断商品一致性 | 编造商品事实 |
| 两个 SKU 混传 | 指出冲突并请用户分组或选择 | 合并为一个商品执行 |
| 用户说“这张”但有多张 | 提供带缩略图的选择 | 猜测后扣费 |
| 请求超出已开放能力 | 说明限制并保留目标，提出可执行部分 | 假装工具已运行 |
| 修图失败 | 展示费用实际状态、保留输入、提供明确重试入口 | 裸状态码或虚报未扣费 |
| 外部结果未知 | 核对原任务状态，提示暂未确认 | 新建付费任务掩盖超时 |
| 重复点击、刷新 | 同一动作仍是同一任务 | 重复收费 |
| 用户停止 | 停止后续动作，说明已提交任务是否可撤销 | 承诺所有外部调用立即取消 |
| 基础检查不通过或主体漂移 | 不作为合格交付，不捕获成功额度；解释处理方式 | 只展示好看的缩略图并宣布完成 |
| 用户拒绝候选 | 保留原版和拒绝原因，可继续或结束 | 覆盖原图、反复自动调用 |

## 验收证据

- 所有图片、反馈与动作都能追到具体素材和版本；客户不能看到其他租户内容。
- 任务状态来自真实执行记录；模拟模式必须显式标识，不混入真实使用统计。
- 输入、计划、确认、状态恢复、结果比较、下一轮和停止均可由用户操作完成。
- 三项人工确认前不开放正式交付动作；用户能够选择旧版本。
- 失败和未知费用状态分别验证，不用统一“未扣额度”掩盖不确定性。
- 桌面和 390px 手机验证主动作、素材指向与对比；不只依靠源码守卫。
- 真实质量验证包含商品一致性与非目标区域漂移；模型连通、构建通过、示例成功均不能替代。

## 体验记录

每次只收集完成任务所必需的信息：目标、现有处理办法、是否独立完成、人工介入、失败节点、采用版本、采用或拒绝原因、耗时、实际费用、是否再次提交。录屏、公开案例和研究复用分别征求相应用途授权。
