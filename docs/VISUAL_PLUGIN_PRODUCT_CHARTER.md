# VisionQA Visual Plugin 产品章程

版本：`visual-plugin-v0.1`
状态：本地原型阶段，尚未代表通用视觉模型准确率、客户采用或商业成功。

## 1. 产品定义

VisionQA 是一个可嵌入其他智能体的视觉判断与修正插件。宿主智能体负责理解用户任务、维护对话和编排工具；VisionQA 负责读取当前视觉产物及其结构化上下文，判断视觉问题、给出证据和修正方案，并在宿主授予写入权限后执行修改与复验。

它不是一个独立的通用聊天 Agent，也不是只会给图片打分的审美插件。它的基本交付物是：

1. 当前产物哪里存在影响目标的问题；
2. 为什么这样判断，以及证据位于哪里；
3. 应该按什么顺序修正，哪些内容必须保留；
4. 修正后问题是否消失，是否引入新的视觉回归。

## 2. 第一性原理

用户不是为了得到一个分数而调用插件，而是为了在发布、交付或继续修改前回答：“这个视觉产物现在能不能用？如果不能，下一步该改什么？”

因此插件以“上下文中的可交付性判断”为中心。没有目标、受众、平台或必须保留项时，插件返回 `NEEDS_CONTEXT`，不根据自己的偏好编造结论。

## 3. v0.1 支持的视觉产物

首期统一输入模型，但按 profile 分层：

- `web_page`：截图 + DOM/CSS/组件信息，优先支持结构化修正；
- `slide`：渲染图 + 页码/对象信息，首期先给页级判断和修改计划；
- `image`：商品图、海报、信息流图或用户上传的视觉素材；
- `document_render`：PDF 或其他可渲染文件的页面级视觉检查。

服饰电商仍保留为第一个已存在的领域 profile：`ecommerce-apparel`。它提供商品真值、Logo、版型、材质和人物一致性规则，不限制通用内核扩展到网页和演示文稿。

## 4. 核心执行链

`获取产物 → 读取任务上下文 → 建立视觉规则 → 观察证据 → 判断问题 → 生成修正计划 → 请求写入授权 → 执行修正 → 重新渲染 → 前后复验`

每次执行都有最大循环次数、最大输出数和费用上限。插件不进行无上限自我递归，也不自动覆盖原始文件。每个修改产生新的 revision，原始产物可恢复。

## 5. “自己的审美”如何实现

VisionQA 的审美由可追溯的规则和样例组成，而不是一段不可解释的 Prompt：

- 基础原则：层级、对齐、间距、比例、对比度、字体、密度、可读性；
- 场景 profile：网页、PPT、电商图、海报等；
- 品牌 profile：色彩、字体、Logo、圆角、阴影和图像方向；
- 用户偏好：允许保留、必须改变、禁止修改的内容；
- 校准资产：已确认的好例子、坏例子和人工改判；
- 版本记录：每次规则变化都关联 rubric 版本和评审案例。

用户接受或拒绝建议可以产生反馈，但反馈只进入待校准记录，不直接改变线上规则。

## 6. 插件边界

- 只读取宿主明确传入的上下文，不默认读取整段对话或本地磁盘；
- 只在宿主声明能力并获得用户授权后写入文件或调用外部工具；
- 只返回证据充分的判断；证据不足时返回 `NEEDS_CONTEXT` 或 `MANUAL_REVIEW`；
- 不把模型输出、Mock 结果或单次成功写成准确率和商业证据；
- 不把 Provider、API Key、私有文件 URL 或敏感 Prompt 写入前端、日志或 Git；
- 视觉判断、修正计划和实际修改分层，便于在不同宿主上复用。

## 7. Provider 与费用

支持三种运行方式：

1. BYOK 本地模式：用户在本机或宿主环境配置自己的 Key，插件不代收模型费用；
2. 宿主代调用：宿主智能体使用其已授权 Provider，VisionQA 接收脱敏后的调用结果和用量；
3. VisionQA 托管模式：未来由服务端统一调用并计费，当前不启用。

无论哪种模式，账本都记录 Provider、模型、请求类型、输入资产数量、耗时、估算费用和结果 revision。账本不记录密钥和完整私有素材。

## 8. 第一版验收标准

- 本地 CLI 可以校验请求、生成结构化视觉评审结果并写出 JSON；
- 本地 MCP Server 暴露 `review_visual`、`plan_visual_repair` 和 `get_visual_capabilities`；
- Mock Provider 与未来真实 Provider 使用同一请求/响应契约；
- 缺少目标或产物时不会编造视觉结论；
- 修正计划默认只读，写入必须带 `requires_approval=true`；
- 官网首页说明插件定位，不再把登录系统和旧电商 Agent 流程作为首页入口；
- 首页提供一个可拖动、可最小化的悬浮插件窗口原型；
- 构建、契约测试和本地运行命令均可复现。

## 9. 适配顺序

`本地 CLI → 本地 MCP → DeepSeek Harness → Chrome 页面侧边栏 → WorkBuddy → PPT → Figma/其他设计工具`

每个宿主只实现上下文采集、结构读取、渲染、写入授权和结果展示，视觉判断逻辑继续留在 VisionQA Core。
