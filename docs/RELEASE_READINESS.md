# VisionQA 发布就绪检查（本地候选版）

更新时间：2026-10-08

## 当前结论

当前版本可作为 **staging/local release candidate** 继续验收，尚不能标记为正式生产已上线。客户链路、商品级对话上下文、图片版本树、模型调用账本、额度冻结/结算、有界执行循环以及 Mock/真实 Provider 统一接口均已有本地实现和自动化覆盖；真实 Provider 质量、真实 PostgreSQL 多实例、对象存储、线上域名、支付和客户采用仍未形成上线证据。

## 一键验收

在 `D:\VisionQA\web` 执行：

```powershell
npm test
npm run lint
```

`npm test` 现在使用 `test:release`：先构建，再运行核心 Agent/持久化测试、页面/契约/业务测试。这样避免旧的 `pretest → 大量跨进程测试 → build` 顺序在 Windows 内存压力下让构建偶发失败。

如果 Vinext 在构建第 3 阶段出现 `memory allocation ... failed`，先关闭不相关的开发进程，在干净终端单独重试 `npm run build`；这属于发布主机资源问题，不得改成跳过构建或降低测试。

## 必须通过的工程门槛

- `npm test`：构建、核心持久化、契约、页面与产品业务测试全部通过。
- `npm run lint`：0 error。
- 浏览器：`/login → /agent` Mock 链可完成建商品、加载素材、筛查、修正、版本切换、刷新恢复和下载；桌面与 390px 无横向溢出。
- 安全：密钥仅在服务端环境变量；图片不进日志/Git/公开 URL；失败不扣额度；重复点击不重复派发或结算。
- 证据：区分工程可运行、模型有效、客户愿意付款三类证据，不得用 Mock 或合成样本替代后两类。

## 上线前仍未闭合

1. 真实 DeepSeek/Qwen 受控 QA：设置调用次数和费用硬停，人工确认每个输出，不自动重试。
2. 真实 PostgreSQL/私有对象存储 staging：验证租户隔离、重启恢复、签名下载、保留期清理和事务幂等。
3. 真实浏览器验收：错误文案、额度冻结/释放、人工终审、第二轮修正和下载。
4. 运行监控与回滚：健康检查、错误追踪、备份恢复、发布版本标记和回滚演练。
5. 只有以上项目完成并由产品负责人明确确认后，才允许切换正式域名或开放客户入口。

## 禁止越过的边界

- 不把 `gpt-5.6-sol`/`gpt-5.6-luna`作为产品运行 Provider；产品运行保持 DeepSeek/Qwen，Seedance 另行评估。
- 不在没有企业主体、商户号、退款/开票和回调验签准备前开启真实支付。
- 不以一次真实调用、内部素材或模拟客户报告宣称稳定成功率、客户采用或商业收入。
