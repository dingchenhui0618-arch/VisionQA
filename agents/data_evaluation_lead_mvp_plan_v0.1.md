> Owner：Data & Evaluation Lead Agent

> 适用项目：VisionQA / 服饰电商 AI 模特商品图质检 MVP  
> 状态：待 CTO 与外部审查角色批准后执行  
> 依据：`PROJECT_STATE.md`、商业模板 Phase 1 共识标签、复评报告、评测协议 v0.2、门禁 v0.1、四大 Skill 映射 v0.2、结果契约 v0.2。

## 0. 结论先行

MVP 的数据与评测工作必须由五个互相制衡的角色承担，不能让“做数据的人”同时决定 gold、阈值和最终是否通过：

1. **数据治理与数据集工程 Agent**：管理来源、授权、哈希、分组、切分和版本；
2. **受控负例制作 Agent**：基于授权模板制作 LOW 单变量失败变体；
3. **标注运营 Agent**：组织双人独立标注与盲评，不自行裁决；
4. **评测与统计 Agent**：冻结指标、计算结果、做误差分析，不修改模型；
5. **测试与发布质量 Agent**：验证 Schema、门禁、失败降级、回归与发布资格。

当前 53 套素材的身份必须始终写为：

> 购买的可编辑电商模板种子库，可用于内部研发及经许可的第三方模型测试；不是实际投放成品，不含 CTR/CVR/GMV 证据，也不是四大 Skill 的生产级 gold set。

Phase 1 的 15 张共识标签只可称为**研发期商业模板共识锚点**。它们可以检验适用性、字段、商业分数的大致区间和 UI，但不能证明真实模型准确率、细粒度排序、`≥90` 自动候选阈值或商业转化效果。

## 1. 当前证据基线与缺口

### 1.1 已具备

- 53 套授权购买模板的 manifest 与使用边界；
- 15 张商业模板 Phase 1 共识锚点：
  - 11 `APPLICABLE / MEDIUM`；
  - 1 `NOT_APPLICABLE`；
  - 3 `NOT_ASSESSABLE`；
- 统一六项商业指标与固定权重；
- 双评审统一口径总分 MAE `5.73`；
- 可执行的结果 Schema、四大 Skill、门禁和修复 Prompt 结构；
- 模拟 case 可用于契约与门禁流程测试。

### 1.2 明确未具备

- 没有完整 `HIGH` 和完整 `LOW` 商业锚点；
- 现有锚点排序相关仅 `Spearman ρ = 0.311`，不能验证细粒度排序；
- 没有“候选 AI 模特图 + 商品参考图 + SKU 不可变项”的配对 gold；
- 没有真实投放效果、人工返工结果和修复前后版本；
- 不能验证商品忠实度、真人真实性、摄影真实性、材质真实性的准确率；
- 不能批准自动发布。

因此首个真实视觉模型的第一阶段只能被授予：

> **MVP 技术资格（adapter qualification）**

不得被授予：

> **业务准确率认证、生产可用认证或自动发布资格**

## 2. 角色卡：职责、输入、输出、验收标准

## 2.1 数据治理与数据集工程 Agent

### 职责

- 建立数据资产登记、授权和禁止声明；
- 对原图、参考图、PSD 派生图、模型输出计算 SHA-256 与感知哈希；
- 建立 `parent_asset_id / sku_id / generation_batch_id / template_family_id` 分组；
- 负责 development / validation / blind test / future holdout 的组级切分；
- 冻结数据版本、维护变更日志，阻止同源图和近似图跨集合泄漏；
- 仅向模型实现 Agent 提供其获准访问的集合。

### 输入

- `datasets/commercial_template_seed_v0.1/manifest.json`；
- 53 张 JPG 与对应 PSD/RAR 的授权记录；
- Phase 1 共识标签与原始双评审结果；
- 后续受控 LOW 变体 manifest；
- 未来获授权的候选 AI 图、商品参考图、SKU 不可变项及渠道信息。

### 输出

- 版本化 dataset manifest；
- 权利与用途矩阵；
- 资产哈希及近似重复报告；
- 组级 split manifest；
- blind test 访问清单；
- 数据变更和删除审计记录。

### 验收标准

- 所有进入模型调用的资产 `100%` 有来源、许可状态和 SHA-256；
- 同一原图、PSD 家族、SKU、人物身份、生成批次及近似变体不得跨 split；
- 受控负例与其 parent 必须处于同一 split；
- 任何缺少许可或保留期限的真实客户资产不得进入第三方模型；
- 测试集标签不出现在 adapter 的 Prompt、配置、样例和开发日志中；
- manifest 可被脚本解析，asset ID 唯一，历史版本不可覆盖。

## 2.2 受控负例制作 Agent

### 职责

- 从已授权、完整且可评估的模板复制出 6–10 张单变量失败变体；
- 每张只引入一个主失败因素，必要时声明预期联动的次指标；
- 保存原图与变体配对、具体操作、参数和预期降分方向；
- 生成盲评预览，不暴露变体类型；
- 不把合成失败样本描述为客户真实失败案例。

### 输入

- 已授权 PSD/RAR；
- `data_acquisition_high_low_brief_v0.1.md`；
- 商业模板六项指标和权重；
- 数据 Agent 分配的 parent asset 与派生 ID。

### 输出

- 6–10 张 `SYNTHETIC_CONTROLLED_NEGATIVE` 图片；
- 原图—变体配对 manifest；
- 每张图的变更记录、预期主指标、允许联动指标和禁止变化项；
- 盲评 contact sheet；
- 原图/变体像素尺寸和哈希。

### 验收标准

- 每个变体可追溯到一个授权 parent；
- 每个变体只有一个主操纵因素；
- 商品本身、人物身份、SKU、价格事实和非目标内容不被意外改变；
- 两名独立评审中至少一人正确识别预期失败，分歧进入外部视觉审查；
- 变体不能靠空白占位、破图、水印或跨渠道来伪造 LOW；
- 所有变体带 `SYNTHETIC_CONTROLLED_NEGATIVE`，禁止写成真实客户或实际投放失败；
- 修改图片前必须先通过本文件第 3 节规范评审。

## 2.3 标注运营 Agent

### 职责

- 制作匿名、盲化标注包；
- 分配 Reviewer A / B，确保独立提交与锁定；
- 检查字段完整、权重计算、等级推导和证据描述；
- 自动生成分歧清单并提交裁决员；
- 保存 A/B 原始标签，不允许查看对方结果后静默改写；
- 维护标注员校准集、重复 case 和自身稳定性记录。

### 输入

- 冻结的数据 split；
- taxonomy、gates、商业模板、标注协议；
- 空白标注表和盲评图片；
- 外部裁决角色名单。

### 输出

- Reviewer A/B 原始标签；
- 校验报告；
- 分歧清单与双方依据；
- 裁决输入包；
- 裁决后共识标签与 provenance。

### 验收标准

- A/B 在相互不可见条件下完成；
- 标签字段、版本、asset ID、证据和置信度完整率 `100%`；
- 总分可由子分重算，等级可由阈值自动推导；
- 强制裁决条件无遗漏：适用性不一致、跨两档、总分差 `>15`、任一子项差 `>20` 或证据矛盾；
- 评审员与同一 case 的裁决员不能是同一角色；
- 原始标签与裁决标签同时保存；
- 任何“标准不足”必须保留为 `REVIEW/NOT_VERIFIED`，不得为提高一致率强行通过。

## 2.4 评测与统计 Agent

### 职责

- 在运行前预注册数据版本、指标、阈值和失败条件；
- 执行模型输出解析、指标计算、置信区间与分层错误分析；
- 分离 adapter 可靠性、商业模板敏感性、四大 Skill 准确率和业务效果；
- 对每次模型/Prompt/规则变化生成可比较报告；
- 发现数据不足时明确输出 `NOT_VALIDATED`，不补造结论。

### 输入

- 冻结模型快照、adapter、Prompt、规则和数据版本；
- 模型原始响应与结构化结果；
- 共识标签、split manifest；
- latency、成本、错误和重试日志。

### 输出

- 机器可读 metrics JSON；
- 人类可读评测报告；
- 混淆矩阵、失败样本清单和错误分类；
- 版本对比报告；
- Go / Conditional Go / No-Go 建议，但不单方面批准发布。

### 验收标准

- 所有指标可由原始结果重复计算；
- provider error、timeout、invalid output 和重试全部入账；
- 不挑选重复运行中“最好的一次”；
- 不在盲测后修改阈值再宣布同轮通过；
- 当前商业锚点必须同时报告 MAE 和 Spearman，不能只报达标的 MAE；
- 四大 Skill 无配对 gold 时必须报告“未验证”，不能从模板图推导准确率；
- 报告必须区分研发锚点、受控合成负例、真实业务 gold 和真实业务效果。

## 2.5 测试与发布质量 Agent

### 职责

- 验证 provider adapter 的契约、异常处理、版本记录和可复现性；
- 验证门禁永远优先于软评分；
- 检查 UI、API、数据库和离线评测字段一致；
- 建立 regression suite，阻止已修复 bug 回归；
- 依据预注册门槛判断构建是否具备 MVP 技术资格。

### 输入

- `evaluation-result-v0.2.schema.json`；
- adapter 与规则引擎构建；
- 契约 smoke set、商业基准集和预期结果；
- 历史 bug 与回归用例。

### 输出

- 自动化测试报告；
- Schema/契约兼容报告；
- 门禁不变量报告；
- 失败降级、超时、重试和审计测试报告；
- 发布候选验收单。

### 验收标准

- 所有结构化输出 Schema-valid；
- `PROVIDER_ERROR / TIMEOUT / INVALID_OUTPUT / INSUFFICIENT_INPUT` 均不得静默变成 `PASS`；
- 任一确认 Blocker 被总分抵消次数必须为 `0`；
- scope 不足时不得声称商品忠实度或品牌符合；
- run 中模型快照、Prompt、adapter、数据、taxonomy、gate、score 和 threshold 版本可追溯；
- 任何适用性、门禁、分数和 Prompt 字段在 API/UI/DB 间语义一致；
- 不通过项必须阻断技术资格，不允许只以 UI 演示正常替代。

## 3. LOW 受控失败变体制作规范

本节只定义制作规范；当前任务不修改任何图片。

### 3.1 Parent 选择

- 选择 `APPLICABLE`、完整、无占位区、无明显结构错误的授权模板；
- 优先从 80–86 分 MEDIUM 中选择，不从 `NOT_APPLICABLE / NOT_ASSESSABLE` 派生；
- 至少使用 4 个不同 parent，避免模型只记住单一版式；
- 同一 parent 最多制作 2 个变体；
- parent 与所有变体必须作为一个 group 切分。

### 3.2 首批 8 个建议变体

| 变体类型 | 主操作 | 预期主指标 | 允许的次级联动 | 禁止变化 |
|---|---|---|---|---|
| N01 主体过小 | 商品/模特等比缩小，使缩略图识别明显变慢 | 商品主体突出度 | 点击动机 | SKU、人物、价格、文案 |
| N02 主体被遮挡 | 促销卡片覆盖商品关键轮廓或结构 | 商品主体突出度 | 点击动机、图位适配 | 商品像素本身、价格事实 |
| N03 卖点泛化 | 具体材质/功能卖点替换为“时尚/新品”等泛化口号 | 卖点表达清晰度 | 点击动机 | 商品、价格、布局 |
| N04 卖点过小 | 保留原卖点但缩至移动缩略图不可读 | 信息可读性 | 卖点表达清晰度 | 文案内容、商品、价格 |
| N05 价格竞争 | 原价、到手价、券后价做成相同视觉权重 | 促销信息层级 | 信息可读性 | 价格数字真实性、商品 |
| N06 优惠堆叠 | 增加多个视觉同权的优惠门槛或活动标签 | 促销信息层级 | 信息可读性、点击动机 | 商品与原有价格事实 |
| N07 安全区破坏 | 将关键商品/价格/CTA 推至裁切风险区 | 渠道与图位适配 | 信息可读性 | 内容本身 |
| N08 CTA 弱化 | 移除/弱化进入详情的动作入口或利益点 | 点击动机 | 卖点表达 | 商品、价格、主布局 |

如无法在不编造价格事实的前提下完成 N05/N06，必须改用纯视觉层级调整，不得创建虚假的客户价格或促销承诺。

### 3.3 制作记录的强制字段

- `variant_id`；
- `parent_asset_id`；
- `source_rights_ref`；
- `operation_type`；
- `operation_parameters`；
- `primary_target_metric`；
- `allowed_secondary_metrics`；
- `locked_content`；
- `expected_direction`；
- `editor_agent_version`；
- `asset_sha256`；
- `perceptual_hash`；
- `synthetic_flag=SYNTHETIC_CONTROLLED_NEGATIVE`；
- `external_visual_review_status`。

### 3.4 单变量隔离验收

制作完成后由标注运营 Agent 盲化，交给两位评审：

- 目标主指标相对 parent 的双评审共识降幅建议至少 `10` 分；
- 8 个变体的目标主指标中位降幅目标至少 `15` 分；
- 未声明联动的其他指标绝对变化中位数不超过 `8` 分；
- 至少 `80%` 的变体获得方向一致的主指标降分；
- 若一个变体出现商品事实、人体或合规新问题，则该变体作废，不能用于商业单变量测试；
- 若评审认为变化只是风格偏好而非商业失败，提交外部创意/电商审查，不强行纳入 LOW。

这里的 LOW 是**受控商业失败负例**，用于敏感性与因果方向测试，不是生产中自然发生的 LOW 分布。

## 4. 首个真实视觉模型 Adapter 基准

## 4.1 基准目标

首个 adapter 必须回答四个问题：

1. 能否稳定调用真实视觉模型并保留原始响应、版本、耗时、成本和错误？
2. 能否按 `evaluation-result-v0.2` 返回有效结构？
3. 在信息不足或模型失败时，能否安全降级而不是误放？
4. 能否对授权模板的适用性和受控商业失败产生正确方向的响应？

它**暂时不回答**四大 Skill 是否准确，也不回答自动发布阈值是否成立。

## 4.2 分层基准集

### B0：契约与门禁 Smoke Set

- 来源：12 条 simulation case 及测试构造的 provider error/timeout/invalid output；
- 用途：Schema、解析、错误映射、门禁优先级、审计字段；
- 声明：无真实图片，不计算模型准确率。

### B1：商业模板研发基准

- 15 张 Phase 1 共识锚点；
- 新制作并通过盲评的 6–10 张 LOW 受控失败变体；
- 对应 parent 图；
- 模板固定为 `platform_promotion_main_image_v0.1`；
- 用途：
  - `APPLICABLE / NOT_APPLICABLE / NOT_ASSESSABLE` 行为；
  - 六项商业分数与总分大区间；
  - parent—variant 方向敏感性；
  - 证据、差距和修复 Prompt 的结构完整性。

B1 的 11 张 MEDIUM 标签可用于 MAE，但因没有 HIGH/自然 LOW 覆盖，Spearman 与等级边界只报告，不作为当前阻断门槛。

### B2：四大 Skill 与 Blocker 业务基准

状态：`BLOCKED_BY_MISSING_PAIRED_GOLD`。

启动至少需要 20–30 组：

- 候选 AI 模特图；
- 商品参考图；
- SKU 不可变项；
- 目标渠道/图位；
- 双人独立问题标签与裁决；
- 至少覆盖无缺陷、疑似、Major、Blocker 和信息不足；
- 同 SKU/同批次组级切分。

B2 就绪前，HUM/PHO/MAT/PF 的准确率、Blocker recall 和危险误放率全部标记 `NOT_VALIDATED`。

## 4.3 运行协议

- 冻结 `model_snapshot / adapter_version / prompt_version / schema_version / taxonomy_version / gate_version / score_policy_version / threshold_policy_version / dataset_version`；
- 每个 B1 case 固定输入重复运行 3 次；
- 不选择最佳结果；
- 自动重试上限固定，所有 attempt 均入日志；
- 原始响应只追加、不覆盖；
- 对完全相同输入计算配置哈希；
- 证据区域使用标准坐标系，不能继续使用 UI 写死坐标；
- 如果模型只支持自由文本，由 adapter 负责解析并保存原文；解析失败计入 `INVALID_OUTPUT`。

## 4.4 MVP 技术资格门槛

### 必须全部通过

| 类别 | 指标 | 通过门槛 |
|---|---|---:|
| 契约 | 最终结构化结果 Schema-valid rate | 100% |
| 追溯 | 必填版本、哈希、原始响应引用完整率 | 100% |
| 安全 | provider/timeout/invalid/输入不足静默 `PASS` | 0 次 |
| 门禁 | 确认 Blocker 被软分抵消 | 0 次 |
| 适用性 | 3 张 `NOT_ASSESSABLE` 与 1 张 `NOT_APPLICABLE` 正确安全处置 | 4/4 |
| 商业绝对区间 | 11 张 MEDIUM 的 `fit_score` 对共识 MAE | ≤10 |
| 变体方向 | 受控变体目标主指标低于 parent 至少 10 分 | ≥80% 变体 |
| 变体总分 | 受控变体商业总分低于 parent | ≥80% 变体 |
| 稳定性 | 同 case 三次适用性结论一致率 | 100% |
| 稳定性 | 同 case 三次商业总分标准差 | ≤5 |
| 可解释 | 需优化 case 至少一个可核验证据与结构化差距 | ≥90% |
| Prompt | 需优化 case 输出可复制 Prompt，且包含锁定项/动作/负约束/策略 | ≥90% |

### 报告但暂不阻断

- Spearman 排序相关；
- p50/p95 latency；
- 单图成本；
- issue 集合 Jaccard；
- 六项商业子分 MAE；
- evidence region 的人工可核验率；
- HIGH/LOW 分类准确率。

这些指标暂不阻断的原因不是不重要，而是当前样本没有完整 HIGH/自然 LOW、人工自身排序一致性不足或尚无区域 gold。

### 任一即失败

- 使用测试标签、asset ID 对应结论或 gold 文案写入 Prompt；
- 把购买模板称为真实投放、生产 gold 或转化证据；
- 缺少参考图时仍宣称商品忠实度已验证；
- 错误、超时、不可读或信息不足被转换成 `PASS`；
- 修改测试阈值后仍把同一轮结果称为盲测；
- 不保存失败响应或通过静默重试隐藏失败；
- 用 B0/B1 宣称四大 Skill 准确率或自动发布可用。

通过上述门槛后的正式措辞应为：

> 该 adapter 通过 VisionQA MVP 技术资格与研发期商业模板敏感性测试，可进入人工辅助内部评估；四大 Skill 准确率、危险误放率、真实业务收益及自动发布能力尚未验证。

## 5. 防数据泄漏规则

### 5.1 数据分组

- 原图、裁切、压缩、PSD 派生图、受控变体按 `parent_asset_id` 同组；
- 同 SKU、人物、生成批次、Prompt 模板和近似图按组切分；
- SHA-256 查精确重复，感知哈希/图像嵌入查近似重复；
- 先分组后切分，禁止逐图随机切分。

### 5.2 权限与盲测

- adapter 实现 Agent 只接触 development/validation；
- blind test 标签由数据 Agent 保管；
- 测试 Agent 通过 runner 运行 opaque case ID，评测 Agent 在冻结输出后解封标签；
- 共享文件系统不能视为权限隔离；必须通过目录约定、日志审计和交付清单进行组织隔离；
- 外部模型调用不得包含 gold 分数、等级、裁决理由或文件名中的标签。

### 5.3 迭代纪律

- validation 可用于选择候选版本，blind test 只用于冻结候选；
- blind test 失败后若修改 Prompt/adapter/规则，必须生成新版本，不得覆盖旧结果；
- 已查看 blind test 错误的版本不能继续声称对同一集合“首次盲测”；
- 下一轮应使用 future holdout 或新时间段数据；
- 原始响应、解析结果、最终结果和人工改判分别保存。

### 5.4 第三方模型数据治理

- 调用前核对授权允许第三方模型测试；
- 记录供应商、模型、区域、保留策略和是否用于训练；
- 能关闭数据训练/保留时使用对应设置并留证；
- 未确认的真实客户素材不得上传；
- 不向外部模型发送不必要的客户名称、联系人或业务敏感字段。

## 6. 必须交给外部审查角色的结论

以下事项不得由内部 Agent 自行宣布最终成立：

| 审查角色 | 必审结论 | 所需证据 | 通过产物 |
|---|---|---|---|
| 外部创意总监/电商视觉专家 | LOW 变体是否是真实可理解的商业失败，而非粗暴破坏或个人审美 | parent/variant 盲图、变更记录、双评审分数 | 变体接受/返工/作废清单 |
| 电商运营/商业顾问 | 六项商业指标、权重、HIGH/LOW 含义和 `≥90` 候选阈值是否符合实际工作 | 共识锚点、真实优质图、错误成本说明 | 模板版本与阈值审查意见 |
| 独立评测审查者 | split、泄漏控制、指标和统计结论是否足以支持声明 | manifest、哈希报告、预注册指标、原始运行 | 方法审查与可声明范围 |
| 合规/数据责任人 | 素材是否可上传第三方、保存多久、能否再分发 | 权利记录、供应商条款、数据流 | 数据处理批准或限制 |
| 业务 Owner | 危险误放与过度拦截的容忍度、试点抽检比例 | 混淆矩阵、错误案例、运营成本 | 受控试点 Go/No-Go |

外部审查的强制触发点：

1. 接受任何 LOW 变体进入冻结基准；
2. 引入 5–8 张 HIGH 公认优质样本并冻结标杆；
3. 调整六项权重或 `90/70` 阈值；
4. 宣称模型准确率、商业可用或生产可用；
5. 从人工辅助升级为自动发布；
6. 使用真实客户素材或改变第三方数据处理方式。

## 7. 交付顺序与 Agent 接口

### Wave D1：数据基础

1. 数据治理 Agent 冻结 `commercial_mvp_benchmark_v0.1` manifest 草案；
2. 受控负例制作 Agent 只提交制作计划和 parent 候选；
3. 外部创意审查批准计划后才允许修改 PSD；
4. 标注运营 Agent 对完成的变体做双人盲评；
5. 数据治理 Agent 将合格变体与 parent 同组入库。

### Wave D2：模型技术资格

1. 模型 Adapter Agent 仅拿开发契约和获准的 development 集；
2. 测试 Agent 先执行 B0；
3. 评测 Agent 执行 B1 三次重复；
4. 测试 Agent核对门禁、安全降级和契约；
5. 独立评测审查者确认报告措辞；
6. CTO 只在证据齐全后授予“技术资格”。

### Wave D3：真实业务准确率

1. 数据治理 Agent 接收 20–30 组配对业务素材；
2. 标注运营 Agent 组织 A/B/C；
3. 评测 Agent冻结 B2；
4. 模型 Agent只在 development/validation 迭代；
5. blind test 后由外部审查角色给出受控试点意见。
