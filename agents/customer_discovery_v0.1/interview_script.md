# VisionQA 问题访谈与价格敏感度脚本

状态：`READY_TO_RUN / NO_RESPONSES_RECORDED`

## 研究原则

- 不把本项目 87 张素材的提供行为当作痛点或付费证明。
- 前 20 分钟不演示产品，不问“你会不会用”。
- 只追问最近发生的具体事件，不接受纯观点替代行为。
- 受访者授权前不录音；记录匿名编号，不记录不必要个人信息。
- 客户素材不上传到未获批准的外部服务。
- 研究员不能承诺准确率、自动发布安全、节省人力或提高转化。

## 招募筛选（5 分钟）

1. 过去 30 天，你们是否实际生产或审核过服饰 AI 模特商品图？
2. 大约多少张候选图进入审核？不是最终发布张数。
3. 是否有候选图对应的 SKU/商品参考图？
4. 谁做首轮检查，谁最终批准？
5. 是否发生过返工、淘汰、平台图片问题或发布后发现错误？

合格条件：问题 1 为“是”，且具备高频批量、独立复核、真实返工或渠道风险中的至少两项。低量探索者可记录，但不进入核心 WTP 样本。

## 第一段：重建最近一次真实批次（10–15 分钟）

“请不要概括平时流程，带我从最近一个已经完成的批次开始。”

1. 这批是什么商品、哪个渠道和图位？何时完成？
2. 输入多少张候选图，最终用了多少张？
3. 第一个人收到什么材料？缺什么材料？
4. 他/她逐步用了哪些工具，做了哪些判断？
5. 一共经过几个人、几轮、多久？
6. 哪张图最难判断？为什么？
7. 哪类问题最常返工？最近一次具体是什么？
8. 最终谁承担“放行错误”的责任？
9. 如果审核人当天不在，流程会怎样？
10. 有没有系统自动检查？它抓得到什么、漏掉什么？

追问证据：

- 能否提供脱敏后的批次统计、返工标签、诊断截图或时间记录？
- 如果不能，下一次是否允许研究员现场计时？

## 第二段：成本与痛点强度（5–8 分钟）

1. 这一批每个角色大约花了多少分钟/小时？
2. 返工由谁完成？内部成本、外包单价或合同 SLA 是什么？
3. 延迟一天会发生什么？“没什么”也是有效答案。
4. 最近 30 天同类问题发生几次？
5. 你们为解决它尝试过什么？为什么没有继续？
6. 如果未来一年什么都不改，谁最受影响？
7. 这件事在本季度优先级排第几？排在它前面的是什么？

记录：

```text
月候选图量 =
首轮审核总小时 =
平均返工轮次 =
平台拒绝/发布错误次数 =
当前软件月费 =
当前外包月费 =
完全负担人工时薪（若对方愿意提供） =
```

不要代客户计算“节省 80%”。可在访谈后给出区间并让客户校正。

## 第三段：现有替代方案（5 分钟）

1. 如果增加一倍图片量，你会先招人、加班、外包还是买工具？
2. 当前群聊/表格/proofing/DAM/平台诊断中，哪一步最不可替代？
3. 当前方案最好的地方是什么？
4. 过去是否评估过其他软件？为什么没买？
5. 数据是否允许进入第三方模型或云？保存多久、谁可访问？
6. 采购一个新工具需要谁同意、走多久、用哪个预算？

## 第四段：概念测试（仅完成问题访谈后，8–10 分钟）

用一句话展示：

> “一个面向服饰电商 AI 模特图的发布前人工辅助审核工作台：批量上传候选图和商品参考，输出门禁、0–100 排序、真人/摄影/材质/商业模板证据、可复制修复 Prompt，并要求人工终审和记录改判。”

任务：

1. 请用你自己的 10–20 张已授权图片完成一次批次；
2. 不解释界面，观察受访者是否能创建批次、理解结果、复核、复制 Prompt、上传返工版本并完成复审；
3. 让受访者指出哪一步会阻止其把工具带回团队；
4. 问“哪一部分与你现有工具重复，哪一部分是新增价值？”

成功信号：

- 能独立完成闭环；
- 愿意提供下一批真实素材；
- 愿意邀请实际审核人；
- 愿意进入带价格试点。

## 第五段：价格敏感度（5–8 分钟）

### A. Van Westendorp（先问，不展示本项目区间）

以“每团队每月、包含约定图片额度”为统一单位：

1. 低到让你怀疑质量或服务不可信的价格是多少？
2. 很划算、无需太多审批的价格是多少？
3. 开始觉得贵，但仍会考虑的价格是多少？
4. 贵到不会购买的价格是多少？

同时记录币种、税、图片量、席位和服务边界。样本少于 20 时只看分布和异常，不计算“最佳价格点”作为定论。

### B. Gabor-Granger（在受访者实际体验后）

按 ICP 使用 `wtp_hypotheses.csv` 的价格梯子，随机决定从中间、偏低或偏高档开始，避免所有人受到同一锚定。

每一档都问：

> “在刚才的范围和限制下，如果本月要签并付款，价格为 X，你会买吗？”

答案只允许记录：

- `YES_NOW`：愿意进入合同/付款；
- `YES_IF`：明确前置条件；
- `NO_BUDGET`；
- `NO_VALUE`；
- `NO_TRUST`；
- `NO_AUTHORITY`；
- `NO_TIMING`。

每次变档只改变价格，不同时改变图片量、功能和服务。

### C. 行为验证

结束时提出：

> “我们可以提供一个 4–6 周、范围固定、保留人工终审的付费试点。你愿意让哪位预算负责人参加下一次会议？如果通过，你们的合同/付款最早时间是什么？”

强信号从低到高：

1. 愿意二次会议；
2. 引入审核人和预算人；
3. 提供真实基线与样本；
4. 接受带金额提案；
5. 签约/付定金；
6. 实际付款和复购。

## 反例与终止问题

- 什么情况下你绝对不会用？
- 哪类误判比多花人工更糟？
- 如果系统仍要求 100% 人工终审，还有价值吗？
- 如果只做排序和证据、不自动放行，值多少钱？
- 现有工具新增哪个功能就会让 VisionQA 没必要？

## 访谈后 10 分钟评分

| 项 | 0 | 1 | 2 |
|---|---|---|---|
| 高频批量 | <100/月 | 100–999/月 | >=1000/月 |
| 痛点近期性 | 无事件 | 90 天内 | 30 天内 |
| 可量化成本 | 无 | 粗略 | 有记录 |
| 决策权限 | 无 | 影响者 | 预算人 |
| 数据可用 | 不可 | 可脱敏 | 可受控试点 |
| 付费行为 | 无 | 二次会议 | 带价提案/付款 |

总分 `>=9` 才进入设计伙伴候选。评分阈值本身也是假设，10 次访谈后复盘。
