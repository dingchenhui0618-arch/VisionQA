# Customer Discovery → MVP 第二轮回灌

状态：`ENGINEERING_INPUT / EVIDENCE-GATED`

## 决策原则

优先级严格按：

1. 跑通闭环；
2. 验证产品功能；
3. 建立数据反馈。

任何客户发现改动都不得阻塞真实模型 canary、受控人工复核和审计主线。新增能力只有在能缩短整体时间、形成独立资产或降低错误率时进入工程队列。

## P2：暂缓

| 项 | 暂缓理由 | 重新开启条件 |
|---|---|---|
| 自动发布 | 当前无 gold、无真实模型准确率、验证期要求 100% 人工复核 | Blocker 召回/危险误放达到冻结门槛且外审批准 |
| 完整 DAM/项目管理 | 与成熟产品正面重叠，不能帮助当前模型闭环 | 客户明确愿为替换现有 DAM 付费 |
| 自动改图/Photoshop 替代 | 产品定位是评估与优化闭环，改图会扩大技术和责任边界 | Repair Prompt 采纳高且客户明确要求一键返工 |
| 视频、3D、非服饰垂直 | 当前 87 张与标准仅支持静态服饰商业图探索 | 首场景通过受控试点并出现明确相邻需求 |
| 企业平台 API/白标销售 | 集成、安全和采购周期长，可能阻塞功能验证 | 前三类 ICP 已出现稳定付费且 API design partner 明确 |
| 与 GMV/CTR 绑定的效果定价 | 没有投放数据、归因和对照实验 | 客户同意共享可审计基线并建立实验设计 |

## 数据缺口：87 张素材如何用

可做：

- 验证图片解码、尺寸、批次导入和上下文字段；
- 从 49 张 development reference 中抽样做界面联调；
- 对 19 张 calibration review 做双人评分口径训练；
- 保留 19 张 evaluation holdout，不用于提示词调优；
- 按 shoot group 防止同系列泄漏。

不可做：

- 把“优秀且已使用”的背景当作 CTR/CVR/GMV ground truth；
- 用偏正向的 87 张证明 REJECT/LOW 能力；
- 未经治理门上传 Qwen 或云；
- 把初判 `MODEL_PRESENT/PRODUCT_ONLY` 当正式标签；
- 把建议拆分当已物化数据集。

必须补：

1. 人工复核分类与 shoot group；
2. 候选 AI 图 ↔ SKU 商品参考图配对；
3. 原始人工审核结论及原因；
4. 经授权的真实返工/拒绝/低质量样本；
5. 返工前后版本；
6. 审核耗时和改判；
7. 渠道/图位/品牌模板上下文。

## 工程 Agent 第二轮优先级清单

```text
1. 审计现有实现是否已完整覆盖 CD-P0-01..06；只补缺口。
2. 用模拟数据跑通：创建批次→评估→人工复核/改判→复制Prompt→上传返工版→复审→完成批次→导出指标。
3. 为每一步生成可机器校验的事件和测试，不只做 UI。
4. 对 87 张客户素材先做本地导入/字段可用性验证，不调用外部模型。
5. 真实模型 canary 获批后，用独立小样本验证输出契约与人工反馈写入。
6. 客户访谈达到进入条件后，才拉取对应 P1；否则保持 HOLD。
```

### 第二轮验收

- 闭环可以由一个测试用户在单次会话中完成；
- 所有业务结论有人工状态和版本；
- 可以导出计算价值所需的最小指标；
- 技术失败、不可评估和业务 REVIEW 不混淆；
- 不新增未被客户证据支持的复杂角色、集成或多垂直；
- 不改变 87 张素材治理边界；
- 外部审查能从事件和导出复核结论。

## 总结

- **必须改/确认**：上下文、人工反馈、计时、Prompt 行为、返工链和批次指标。
- **需验证**：商业模板 onboarding、平台规则包、多客户工作区、按图计费和集成。
- **暂缓**：自动发布、完整 DAM、自动改图、跨垂直、平台 API 白标和效果分成。

总体置信度：`MEDIUM`。P0 大多来自已冻结产品闭环和明显数据缺口；P1/P2 的商业优先级仍需真实访谈。  
下一验证动作：工程 Agent 先做差距审计并回报每项 `EXISTS / PARTIAL / MISSING`，Customer Discovery 同步执行 14 天访谈；两条线互不阻塞。
