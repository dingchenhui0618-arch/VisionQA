# VisionQA Repair Benchmark Curator v0.2

日期：2026-08-27
性质：**下一版 ImageGen 合成案例库契约建议**；不是素材库、模型运行记录或客户结果。

## 审查结论与使用边界

- `repair_benchmark_v0.1` 的 12 例都是计划条目（`NOT_RUN`）；它的 Gold Label、盲测分离、五项可观察验收和人工终审要求可直接继承。
- `CARDIGAN_E2E_CASE_v0.1` 是 `SYNTHETIC_INTERNAL_TEST_ONLY` 的单个流程记录。即使其中记录了受控修正和实现方复验，独立 QA 未完成，故**不得**填入基准成功率、模型有效性、客户采用或商业证据。
- 未发现使验收不可观察的硬性矛盾。需在 v0.2 明确隔离“端到端流程试跑”和“盲测已验收”：前者只能提供候选设计灵感；后者必须有独立 Gold Label 与盲测包。
- 本建议只定义后续 ImageGen 合成资产的构成与验收；不要求调用 ImageGen，不读取或复用客户私有素材。所有新资产生成前均标为 `PLANNED_SYNTHETIC / NO_MODEL_CALL`。

## v0.2 合成案例库总契约

### 证据与权限

每例必须有独立目录和 manifest，并固定下列标签：

- `evidence_mode=SYNTHETIC_INTERNAL_TEST_ONLY`
- `asset_origin=IMAGEGEN_SYNTHETIC_INTERNAL`（生成后才可写为实际来源；计划阶段写 `PLANNED_IMAGEGEN_SYNTHETIC`）
- `execution_claim=NO_MODEL_CALL`，直到另行记录实际执行；不得用“素材已生成”替代修正模型已运行。
- `not_real_customer_evidence=true`、`not_model_effectiveness_evidence=true`、`not_commercial_evidence=true`
- `blind_review_required=true`、`human_final_review_required=true`、`auto_pass_enabled=false`

每例的角色和文件最少包括：

1. `truth/`：无缺陷 SKU 真值板（正面、背面、侧面；需要时增加局部特写）、结构化 SKU 事实和渠道规格；
2. `candidate/`：只含一个预设主问题的受控缺陷候选图；
3. `gold-label.json`：候选与每张真值的 SHA-256、允许范围、禁止变化区、策略、再生/阻断触发条件；
4. `repair-brief.md`：给执行方的最小修改 Brief；不可放入盲测包；
5. `blind-packet/`：原图、真值、用途规格、可观察问题、禁止区和随机输出代号；不得包含 Provider、Prompt、模型版本或候选顺序；
6. `review/`：独立验收五项逐项证据及人工终审签署。没有此目录中的完整记录，案例仍为 `NOT_RUN`。

合成 SKU 只能使用虚构、无品牌冲突的款式和测试标记。若案例包含 Logo/字标，须使用专为测试创建且可再分发的虚构 SVG/PNG；修复采用确定性合成，不要求生成模型猜写文字。

### 统一操作 Gate

`自动候选问题 → 用户/美工确认 → 有边界的受控修正 → 自动大漂移拦截 → 独立盲测 → 人工终审`

- 自动候选只可列出“待确认问题 + 位置 + 置信/不确定性”；不能自动选修图范围、自动选候选或自动交付。
- 用户确认必须选择唯一主问题、目标区域、允许策略与交付规格。信息不足时只可 `BLOCKED`，不可让模型补猜 SKU 事实。
- 现有粗粒度漂移 Gate 的 `ALLOW_HUMAN_REVIEW` 只允许进入人工复验；不是 `PASS`，也不是局部 SKU 正确的证据。
- `LOCAL_REPAIR` 只适用于单一、可见、可由对应视角真值核验的局部问题；发生非目标漂移则 `REWORK`，越过局部边界则 `REGENERATE`。
- `REGENERATE` 用于脸部/身体比例、主体裁切、镜头或多个关键 SKU 结构的整体错误；禁止把它伪装成“局修成功”。
- `BLOCKED` 用于真值、授权、无遮挡结构、渠道规格或所需能力缺失；阻断本身是正确可验收结果。

## 案例分层

| 层级 | 目标 | 允许主策略 | 通过边界 |
|---|---|---|---|
| L1 微小局部 | 测试单一装饰、面料或小结构的最小修改 | `LOCAL_REPAIR` 或确定性合成 | 一个目标区被修正，目标区外 SKU、人物、背景、画幅不变 |
| L2 局部结构/接触 | 测试局部衣片、手部接触和遮挡边界 | `LOCAL_REPAIR` 或 `LOCAL_REPAIR_OR_REGENERATE` | 对应视角真值足以复核；不得改变身份、姿势或其他衣片 |
| L3 大错/整体重生 | 验证系统能拒绝危险局修 | `REGENERATE` | 正确升级为重生成；没有伪造局部交付 |
| L4 信息/能力阻断 | 验证系统在不可观察条件下失败关闭 | `BLOCKED` | 明确指出缺失项，不生成或交付猜测内容 |

## Prompt 与资产制作守则

1. 每例先生成或绘制真值，再由同一已冻结真值派生**仅一个**主问题的候选；不得把两个独立问题塞入 L1/L2 案例。SB-008 与 SB-009 是有意的整体错误例外，必须明确标成 L3。
2. 提示词描述服装事实、机位、姿势、光线、画幅和单一故障；不要写“修复成功”“客户商品”“真实品牌”“销量/评价”，不要出现水印、价格、营销字幕或未授权品牌字样。
3. 同一案例的真值与候选应锁定：商品款式、虚构模特身份策略、镜头、姿势、光线、背景、画幅。变化只允许出现在 Gold Label 标明的主问题区域。
4. Logo/字标类的 ImageGen 提示词只生成干净承载区域；官方/测试资产的实际放置由可审计的确定性合成完成。这样评的是边界和 SKU 保留，而不是生成文字能力。
5. 生成完成后再计算 SHA-256、记录生成日期、工具/版本（若适用）、合成标识和可再分发许可。该记录是资产溯源，不是修图模型效果记录。

## 验收与报告口径

每个实际运行案例仍按五项独立记录：目标修正、SKU 一致性、人物身份、非目标漂移、交付可用性。每一项必须有 `PASS / CONDITIONAL_PASS / REWORK / REGENERATE / BLOCKED / NOT_RUN` 和可定位的前后证据；不使用平均分代替硬 Gate。

可汇总的仅是冻结样本上的过程指标，例如“已完成独立盲测的合成案例数”“按策略分布的结果数”“阻断是否符合 Gold Label”。报告标题必须包含 `SYNTHETIC_INTERNAL_TEST_ONLY`；不得报告为模型准确率、泛化能力、真实客户成功率、付款、采用、复购或商业验证。

一次案例进入 `PASS` 的最小条件是：真值和授权可核验、用户确认留痕、修正策略未越界、五项观察无硬失败、独立盲测完成、人工终审签署。任何缺失均保持对应状态，尤其 `BLOCKED` 和 `NOT_RUN` 不得被填成通过。

- [ ] 每份 Gold Label 写明商品真值、目标问题、允许修改区、禁止变化区、`LOCAL_REPAIR` / `REGENERATE` / `BLOCKED` 触发条件和五项可观察验收。
- [ ] 自动候选问题已由用户/美工确认；无确认不得发送或执行修正。
- [ ] 盲测验收者与实现方分离，且 blind packet 不含模型、Prompt、实现方或输出顺序信息。
- [ ] 所有合成资产和报告均带内部合成证据标签；没有任何真实客户素材、客户结论或模型有效性表述。
- [ ] `AUTO_PASS_DISABLED` 与人工终审保持开启状态。
