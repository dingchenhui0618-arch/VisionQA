# VisionQA MVP 闭环工程验收 v0.2

状态：`LOCAL_MVP_GO_FOR_DISCOVERY / REAL_MODEL_NO_GO`

## 角色契约

| 项目 | 内容 |
|---|---|
| 职责 | 在不申请 API Key、不上传客户素材、不调用模型的前提下，跑通最小产品闭环。 |
| 输入 | `web/`、评估契约、Fixture、Customer Discovery v0.1 的 P0 回灌要求。 |
| 输出 | 本地候选图入口、确定性 Fixture 回放、提交上下文、人工反馈、Prompt 使用计数、试点指标复制、自动化测试。 |
| 验收标准 | 一次会话可完成候选图输入、结果阅读、人工确认或改判、反馈保存、试点指标提取，并持续显示演示限制。 |

## 本轮实现

1. 本地候选图仅在浏览器读取、预览和计算 SHA-256，支持 JPG、PNG、WebP，最大 20 MB。
2. 哈希只用于确定性选择已有 Fixture，页面清楚声明上传图没有被模型读取或分析。
3. 提交时记录渠道、图位、SKU/参考状态和 AI 来源状态。参考缺失或来源未知时，结果强制为 `REVIEW`。
4. 记录候选追踪号、Fixture case、人工结论、标准化原因、业务备注、审核开始和完成时间、Prompt 复制次数。
5. 人工反馈保存在版本化浏览器记录中。正式评估仍优先走服务端审计，D1 未绑定时会明确降级。
6. 提供“复制试点指标”，用于客户访谈与付费试点记录，内容含上下文、人工结论、审核时长边界、Prompt 使用和演示限制。

## 验收证据

- `npm test`：55 项通过。
- 浏览器本地闭环：候选图载入后得到本地追踪号 `local_*`，Fixture 回放显示为 `FIXTURE_REPLAY_NO_MODEL`。
- 来源未知下的 94 分 Fixture 被界面降为 `REVIEW`。
- Prompt 复制、人工确认、本地反馈和试点指标复制均在界面上返回成功状态。

## 明确限制

- 没有真实视觉模型推理、准确率、自动发布或商业效果证据。
- 本地 Fixture 结果不能用于客户生产决策。
- 87 张客户素材未上传、未复制、未发往外部服务。
- 批次级 CSV/JSON 文件下载、返工版本自动关联和真实耗时基线仍需在受控试点中由真实工作流验证后再决定是否开发。

## 下一步行动

用此本地 MVP 在 10-20 张客户自选、已获授权的图片上完成受控演示。每次必须记录提交上下文、人工结论、返工轮次和审核时长，之后再判断是否进入真实模型 canary。
