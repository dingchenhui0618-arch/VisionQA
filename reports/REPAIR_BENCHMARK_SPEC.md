# Repair Benchmark v0.1：独立修图评测与盲测验收契约

## 结论

`repair_benchmark_v0.1` 已定义为一个**尚未运行**的 12 案例评测计划。它从商品真值出发，分别验证目标修正、SKU 一致性、人物身份、非目标漂移与交付可用性；不以单一综合评分作为客户结论，也不把现有合成素材、内部候选或工程 Gate 冒充模型有效性、客户采用或商业证据。

范围入口：`data/repair_benchmark_v0.1/`。本轮没有外部模型调用、没有新增图片、没有对客户素材进行读取或扩展授权。

## 与现有 Repair Case 的接口

| 层级 | 当前职责 | 本基准新增约束 |
|---|---|---|
| Repair Case | 将候选 SHA、商品真值、诊断、Provider Job、输出、人工复验和 4K 交付串联 | 每个基准案例必须先冻结 Gold Label；实现方和验收方不得由同一角色兼任 |
| `repair-output-gate-v0.1` | 以画幅、24×36 粗粒度指纹、平均差和变化格比例拦截明显重构 | `ALLOW_HUMAN_REVIEW` 仅表示未见大幅构图漂移，不能证明局部 SKU、人物身份或非目标区域正确 |
| 人工复验 | 现有链路需要人工终审、自动放行关闭 | 盲测将五类可观察结果逐项留证；客户界面只显示问题、可带来的改善、修正候选与前后对比，不显示总分裁决 |
| 4K | 本地高质量重采样可生成 4K 像素尺寸 | 只有“尺寸交付”时可通过；不得把插值表述成细节重建。需要真实纹理重建而无获批能力时必须 `BLOCKED` |

## 分类与策略

分类完整定义在 [`taxonomy-v0.1.json`](../data/repair_benchmark_v0.1/taxonomy-v0.1.json)。覆盖：

- Logo/字标：优先以授权官方资产做确定性合成，禁止生成模型猜字；没有资产或位置锚点不能放行。
- 贴花、胶印、刺绣：按局部边缘、工艺和周边织物连贯性验收。
- 颜色、材质、纹理：可局部修正；全身主色或大面积材质失真通常应重生成，不能以滤镜伪造细节。
- 口袋、纽扣、领口、拉链与版型：要有正/背/侧与细节真值；缺视角时不扩大为完整 SKU 通过。
- 人体异常、遮挡接触：小范围手指／边缘错误可探索局修；身份、肢体数量、骨架或关键商品被遮挡且无真值时应 `REGENERATE` 或 `BLOCKED`。
- 背景构图：背景孤立杂物可局修；主体裁切、镜头、比例或场景错误应重生成。
- 2K→4K：区分像素尺寸交付与真实细节重建；后者需单独授权和评测。

策略枚举：`LOCAL_REPAIR`、`DETERMINISTIC_COMPOSITE`、`LOCAL_REPAIR_OR_DETERMINISTIC_COMPOSITE`、`LOCAL_REPAIR_OR_REGENERATE`、`DETERMINISTIC_RESAMPLE_OR_BLOCK`、`REGENERATE`。策略不是模型指令，也不是成功保证；它只限定可被接受的处理边界。

## Gold Label 契约

Gold Label 的目标是冻结“什么应改变、什么绝不能改变、缺什么必须停”，而非保存一个视觉偏好分数。逐案例必须记录：

1. 候选与全部真值文件名、SHA-256、来源与授权状态；
2. SKU ID、已核验属性、参考范围（`FULL_SKU` / `FRONT_ONLY` / `STYLE_ONLY` / `BLOCKED`）；
3. 问题分类、像素/语义目标区域、预期问题、允许策略、禁止变化区与重生成触发条件；
4. 五类可观察结果的可判定文字条件；
5. 标注人、日期、执行声明与说明。执行声明必须区分 `NO_MODEL_CALL` 和另行记录的真实执行。

[`gold-label-template-v0.1.json`](../data/repair_benchmark_v0.1/gold-label-template-v0.1.json) 提供 JSON Schema 和唯一的 `RB-001` 计划模板。该模板虽引用已核验的合成素材 SHA，但仍为 `NOT_RUN`，不纳入任何模型或客户指标。

## 盲测验收契约

### 分离规则

- 实现方可以提出修正 Brief、执行改图或准备候选；不得担任该候选的盲测验收者。
- Gold Label 管理员向盲测验收者提供：原图、SKU 真值、用途规格、目标问题的可观察描述、禁止变化区、随机化输出代号。
- 盲测验收者不得获得 Provider 名称、模型版本、Prompt、温度/参数、候选生成顺序、实现方身份、Gold 的预设结论或任何综合分。
- 盲测包的 `output_token` 必须随机化；映射表由 Gold Label 管理员单独保存，不写入客户界面。

### 五类观察结果

每项单独填写 `PASS / CONDITIONAL_PASS / REWORK / REGENERATE / BLOCKED / NOT_RUN` 和可定位证据：

| 结果 | 观察依据 | 最低安全规则 |
|---|---|---|
| 目标修正 | 目标问题是否已依真值解决 | 问题未解决、引入同区域新结构错误 → `REWORK` |
| SKU 一致性 | 颜色、材质、图案、Logo、结构与适用视角真值 | 硬性 SKU 事实冲突或真值范围不足 → `REWORK` / `BLOCKED` |
| 人物身份 | 同一脸部、姿势、肢体、手脚与服装接触关系；非模特图记 `NOT_APPLICABLE` 并说明 | 身份漂移、额外/缺失肢体、全身比例崩坏 → `REGENERATE` |
| 非目标漂移 | 禁止区域、画幅、镜头、背景、光线、商品其他部件前后对比 | 触发现有本机大漂移 Gate 或人工发现不可接受变化 → `REWORK` / `REGENERATE` |
| 交付可用性 | 渠道画幅、像素尺寸、清晰度、裁切、水印/乱码、格式与 4K 处理凭证 | 未满足明确交付规格、或把重采样伪称细节重建 → `BLOCKED` |

最终 `delivery_state` 不使用平均分或加权总分：

- 五项均可核验且无硬性失败：`PASS`（仍需人工终审签署）。
- 仅有已声明的非关键限制且客户用途可接受：`CONDITIONAL_PASS`。
- 可在不越过禁止变化区的前提下再次修正：`REWORK`。
- 人物、构图或多个关键 SKU 事实必须整体重做：`REGENERATE`。
- 真值、授权、交付规格或所需能力缺失：`BLOCKED`。

盲测表在 [`blind-acceptance-template-v0.1.csv`](../data/repair_benchmark_v0.1/blind-acceptance-template-v0.1.csv)。它的唯一样例行全为 `NOT_RUN`，以免形成虚假的验收记录。

## 最小用户素材清单（本轮不足）

对每个真实 SKU，至少需要：

1. 候选原图及可用于内部评测的明确授权范围；
2. 对应 SKU 的白底正面图，结构问题还需要背面、侧面和相关细节；
3. 颜色/材质问题的受控光线真值和面料近照；
4. Logo、字标、图案问题的已授权官方 SVG/透明 PNG、色值和位置尺寸规范；
5. 模特图的人物身份策略：保留身份所需的授权／参考，或书面标记为不要求保身份；
6. 目标渠道、画幅、尺寸、文件格式，以及“仅需尺寸放大”还是“需要真实细节重建”的交付规格；
7. 被遮挡商品结构的无遮挡真值图或明确允许重生成的决定。

在这些资料补齐前，RB-002 至 RB-012 必须保持 `MATERIALS_REQUIRED / NOT_RUN`。本基准不从桌面或其他目录自行收集、复制或扩大素材授权。

## 当前不足与下一步

- 目前仅有 1 个合成受控输入可用于计划核对；真实授权样本为 0，因而没有盲测一致率、修正成功率、交付通过率或客户采用率可报告。
- 现有粗粒度漂移 Gate 不覆盖局部品牌文字、刺绣边界或微小 SKU 漂移；这些仍依赖本契约中的人工逐项证据。
- 需要真实细节重建的 4K 案例仍取决于独立、获批的超分能力评测；当前本地重采样不能代替该验证。

下一步是在不扩大授权的前提下，由用户提供最小素材包后，为每个案例复制 Gold Label 模板、冻结事实，再把候选交由与实现方分离的盲测验收人复核。
