# 日度客户发现报告 Day 2：服饰电商 AI 模特图修正的真实访谈准备

> 日期：2026-08-27（Asia/Shanghai）
> 性质：`SIMULATION`；不是客户、收入、付款或市场规模证据。
> 目标：为下一轮真实测试人员访谈提供可证伪的问题、观察点和最小事件。

## 1. 证据边界

- `[VERIFIED]` 项目主链路已收敛为：完整 SKU 商品真值 → AI 模特草图 → 问题诊断 → 受控修正 → 前后人工复验 → 本机交付。
- `[VERIFIED]` 灰色针织开衫案例 `CARDIGAN_E2E_CASE_v0.1` 是 `SYNTHETIC_INTERNAL_TEST_ONLY`：结构化 SKU 事实改善了诊断，但仍出现“正确刺绣缺失”的假阳性；一次 Qwen 修正成功，但独立 QA 未完成，不能形成客户交付或模型准确率结论。
- `[VERIFIED]` 自动放行关闭；技术失败、缺少真值、非目标区域漂移和未完成人工终审时，不能形成 `PASS` 或交付结论。
- `[USER-SUPPLIED]` 当前要验证的产品想法是：AI 识别问题或用户直接描述问题，系统生成修图边界，用户通过修改前后对比做人工复验。
- `[HYPOTHESIS]` 任何团队画像、痛点排序、现有返工分钟数、预算、WTP 和复购可能性，当前均未被真实客户验证。

## 2. 哪些服饰电商团队可能最痛（待验证画像）

以下是用于抽样的 `[HYPOTHESIS]`，不是客户结论。访谈必须按“最近一次真实返工”验证，而不是按认同度统计。

1. **高频上新、AI 模特图已进入上架链路的品牌/店群内容团队**：图量多，问题常在上架前后才暴露；疑似最痛的是版型、口袋、纽扣、Logo、颜色等 SKU 事实漂移。
2. **品牌视觉负责人 + 多名美工/外包协作团队**：疑似最痛的是同一张图被多人反复标注，缺少统一的“改什么、什么不能改、谁验收”记录。
3. **平台运营或商品负责人承担最终发布风险的团队**：疑似最痛的是美工认为“能看”，运营却无法确认“能不能上架”，返工会延误发布时间。
4. **使用生成图但没有稳定修图规范的小团队**：疑似最痛的是不断重生会连带改变人物、构图和已正确区域，人工只能重新比对。

不应优先假设最痛的是“没有设计师”的团队；如果其主要问题是从零产图，而不是交付前修正，本产品命题可能不匹配。

## 3. 当前如何由美工/PS 返工（待观察，不预设答案）

访谈中请要求对方演示最近一次流程。下面仅列 `[HYPOTHESIS]` 的候选流程：

1. 美工打开 AI 模特图，与白底图、细节图或官方确认稿并排肉眼对照。
2. 用 PS 图层、蒙版、修补/仿制、局部重绘或重新生成，处理一个明确部位；若没有明确边界，可能直接重做整张图。
3. 将标注截图或文字发到群聊/任务系统，由运营或视觉负责人再次指出问题。
4. 返工后再检查人物、姿势、背景、光线和商品非目标区域是否被带改，并导出上架尺寸。

需要核实的真实替代成本：谁执行、使用什么软件/服务、平均往返轮次、实际耗时、是否延迟上架、是否发生报废，以及是否留存前后文件或任务记录。不要用估算替代记录。

## 4. 什么证据才能证明愿付费

只有下列证据形成后，才可讨论 WTP；“感兴趣”“看起来有用”“愿意试试”均为 `[HYPOTHESIS]`，不算付款证据。

- `[VERIFIED]` 目前没有真实客户付款、真实采用、复购或客户授权素材证据可供本报告引用。
- `[NEXT QUESTION]` 对方能展示一条脱敏的近期返工记录、前后图或任务系统记录，并说明实际责任人和返工原因。
- `[NEXT QUESTION]` 对方在 2–3 个脱敏前后案例上做出“采用/继续返工/放弃”选择，并能指出具体证据，而不是只给分数或偏好。
- `[NEXT QUESTION]` 对方用真实预算流程说明当前为修图、外包或延误支付过什么；金额可不在访谈中透露，但必须说明支出是否真实发生、谁批准。
- `[NEXT QUESTION]` 对方愿意提交一个获授权的真实 SKU 小批次，并在真实上架流程中采用至少一张修正版，记录人工终审结果。
- `[PROPOSED]` 最小商业证据阈值：至少 3 个不同真实客户批次完成授权素材测试，其中至少 2 个批次实际采用修正版进入上架/投放，且至少 1 个批次产生真实付款；未达成前，WTP 结论保持 `NOT RUN`，不建设公开计费。

## 5. 中立访谈问题

问题顺序从事实到流程、决策和预算，避免先展示产品价值或诱导认同。

### 最近事实与影响

1. `[NEXT QUESTION]` 请讲最近一次 AI 模特图被退回或返工的真实案例：哪一张、什么问题、谁发现、在哪一步发现？
2. `[NEXT QUESTION]` 能否展示脱敏的原图、返工图、标注或任务记录？如果不能，哪些证据可以替代？
3. `[NEXT QUESTION]` 当时实际往返了几轮？每轮由谁完成？有没有记录用时、外包费、延迟上架或报废？
4. `[NEXT QUESTION]` 这类问题中，哪些最容易漏掉：颜色、版型、口袋/纽扣、Logo、人物/手部，还是其他？请按最近案例回答。

### 当前美工/PS 方法

5. `[NEXT QUESTION]` 现在如何把白底图、细节图或官方事实与 AI 模特图对照？请现场按步骤演示，不只描述理想流程。
6. `[NEXT QUESTION]` 你会在 PS 中局部修、重新生成，还是交给别人？什么条件会让你改选另一种方法？
7. `[NEXT QUESTION]` 返工后如何确认没有连带改变人物、姿势、背景、光线和商品的其他正确部位？谁拥有最终否决权？
8. `[NEXT QUESTION]` 哪些内容不能上传外部模型？授权、删除、留存、版本和审计要求是什么？

### 对目标产品命题的中立验证

9. `[NEXT QUESTION]` 如果系统只列出“可能的问题、证据位置和不确定性”，你会先确认什么，才允许它提出修图方案？
10. `[NEXT QUESTION]` 对“用户直接描述问题”和“AI 自动识别问题”，你分别担心什么误报、漏报或责任风险？哪一种更符合你现在的流程？
11. `[NEXT QUESTION]` 一份修图边界至少要写清哪些“不变项”？请用一个最近案例举例，而不是评价概念本身。
12. `[NEXT QUESTION]` 看原图与修正版并排对比时，你会检查哪些项目后选择采用、继续返工或放弃？能否在 60 秒内对两个案例做决定并说明理由？
13. `[NEXT QUESTION]` 如果 AI 把一个真实存在的细节误报为问题，你希望如何确认、撤销或留下责任记录？

### 付费与采用

14. `[NEXT QUESTION]` 你现在为类似返工实际支付过什么？是内部工时、外包、生成服务还是延期成本？谁能提供预算或订单依据？
15. `[NEXT QUESTION]` 若真实小批次测试后修正版被采用，你的采购/报销/供应商流程是什么？下一次提交需要满足什么条件？
16. `[NEXT QUESTION]` 什么结果会让你停止使用：误报、非目标漂移、无法追溯、外传风险、等待时间、费用，还是其他？请按真实流程排序。

## 6. KEEP / CHANGE NOW / TEST NEXT / DEFER

### KEEP

- `[VERIFIED]` 保留“商品真值 + 用户确认问题 + 受控修正 + 前后人工复验”的主链路。
- `[VERIFIED]` 保留真实素材与示例隔离、Repair Case 版本链、失败关闭、人工终审和自动放行关闭。
- `[VERIFIED]` 保留对非目标区域漂移、商品关键事实和交付尺寸的显式复验；4K 重采样不宣称细节重建。

### CHANGE NOW

- `[VERIFIED]` 将诊断结果表达为“问题候选 + 证据位置 + 不确定性 + 建议动作”，禁止把模型判断直接写成事实或自动执行修图。
- `[HYPOTHESIS]` 访谈演示首屏应先展示具体问题、修图边界、前后对比和下一步，弱化总分；需通过真实任务选择验证，而非偏好问卷。
- `[VERIFIED]` 每次修正记录用户确认的目标区域与不变区域；技术失败显示为技术失败，不形成商品不合格结论。

### TEST NEXT

- `[NEXT QUESTION]` 招募 2–3 类团队各至少 1 位实际参与返工和验收的人，使用真实授权单 SKU；不以模拟样例的“正确率”替代。
- `[NEXT QUESTION]` 让受访者现场完成：提交真值、描述/确认问题、查看边界、判断前后图、决定采用/返工/放弃，并记录每个事件和理由。
- `[PROPOSED]` 首轮继续测试的工程/体验阈值：至少 70% 的真实任务能在 60 秒内做出有理由的三选一决定；低于此值先改信息呈现，不测试计费。
- `[PROPOSED]` 目标问题人工确认解决率先以 ≥70% 作为继续小批量测试门槛；该数值不是模型准确率或商业结论。

### DEFER

- `[VERIFIED]` 公开账户、复杂租户、自动发布、自动放行、全量云端项目列表和公开支付。
- `[VERIFIED]` 达人爬虫、营销扩展、多智能体自治和与单 SKU 修正无关的功能。
- `[HYPOTHESIS]` 任何月费、按张价格、收入预测或“爆款/成交”承诺，直到真实付款和重复提交证据出现。

## 7. 最小指标事件

这些是观察事件，不是虚构的当前数据；所有数值阈值均需标注为 `[PROPOSED]` 并由真实批次校准。

| 事件 | 最小记录字段 | 指标/用途 |
|---|---|---|
| `interview_case_shown` | 受访者角色、真实案例时间、证据类型、是否获授权 | 真实案例覆盖，不统计口头兴趣 |
| `sku_truth_confirmed` | SKU、真值来源、版本、素材哈希、确认人 | 真值完整率；缺失则 `BLOCKED` |
| `problem_reported_or_detected` | 用户描述/AI 候选、部位、证据、置信/不确定性 | 识别来源与可复述问题比例 |
| `repair_boundary_confirmed` | 目标区域、不变区域、参考图、确认人、时间 | 用户是否理解并接受修图边界 |
| `before_after_reviewed` | 原图/修正版、人工检查项、漂移结果、耗时 | 目标解决率、非目标漂移率 |
| `decision_made` | 采用/继续返工/放弃、理由、决定人、耗时 | `[PROPOSED]` 60 秒内有理由决策率，起始门槛 ≥70% |
| `delivered_or_blocked` | 状态、阻断 Gate、交付版本、下载/采用凭证 | 交付可用率；不得把下载当采用 |
| `real_adoption_recorded` | 上架/投放位置、采用图版本、终审人、日期 | 真实采用证据，与演示成功分开 |
| `payment_evidence_recorded` | 付款/采购凭证类型、批次、客户匿名 ID | WTP 证据；无凭证则 `NOT RUN` |
| `resubmission` | 同一客户/批次、间隔、再次提交原因 | 重复需求；不提前假设复购 |

## 8. 访谈结束时的证伪判断

- `[HYPOTHESIS]` 若团队无法指出最近真实返工、无法提供任何流程证据，或主要需求是从零生图，则“AI 修正边界 + 前后复验”对该团队尚未成立。
- `[HYPOTHESIS]` 若团队能稳定描述 SKU 错误但无法接受外传，产品必须先验证本地/受控处理边界，不应强推在线模型。
- `[PROPOSED]` 若 3 个真实客户批次中，少于 2 个采用修正版，或没有 1 个真实付款批次，则继续保留服务/访谈验证，不把 WTP 视为已证明。
- `[NEXT QUESTION]` 每次访谈最终只问一个可行动结论：这个真实案例下一步愿意授权哪一张图、由谁在什么流程节点复验，以及什么证据会让其停止。

## 9. 当前结论

`[SIMULATION]` Day2 只能提出优先抽样画像、返工流程假设和证伪方法；不能证明哪个团队最痛，也不能证明愿付费。
`[VERIFIED]` 现有合成案例支持“自动识别只能提供问题候选，人工确认与前后复验不可省略”的产品边界。
`[NEXT QUESTION]` 下一轮必须以获授权真实 SKU、真实返工记录、实际采用和真实付款/预算证据为主；在此之前，商业判断保持 `NOT RUN`。
