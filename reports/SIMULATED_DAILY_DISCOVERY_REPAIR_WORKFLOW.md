## 2. 最可能痛点最强的企业画像

**[未验证假设] 画像：中小至中型服饰品牌/店群的内容交付负责人。** 每周持续上新，已有白底商品图和 AI 模特图生产习惯；美工或外包能“生成”，但运营/视觉负责人要在上架前逐张确认。团队不一定缺少审美，而是缺少一套可追溯的商品真值、问题定位和返工闭环。

**[模拟回应]** “最烦的不是图不够多，而是看起来差不多、上架后才发现版型/口袋/颜色/Logo 不对；我需要知道具体错在哪里，最好直接给一张不改人物和构图的可交付版本。”

**[未验证假设] 痛点排序：**

1. 商品结构或关键细节漂移，人工发现晚且返工沟通成本高。
2. 改图后人物、姿势、背景或非目标区域被重绘，无法判断是否真的修好。
3. 不同角色对“能不能上架”的判断不一致，缺少明确证据和责任记录。
4. 评分不能直接告诉客户下一步怎么改，也不能代替可下载的交付文件。
5. 单次处理量、费用和外传范围不透明，客户不敢把真实商品图交给系统。

> **[下一步真实问题]** 以下问题必须问真实从业者并记录原话、最近案例、素材/流程证据；不得用模拟回答填空。

## 7. 用户能理解的问题语言

**[未验证假设/建议文案]** 用这些问题替代模型术语和单独分数：

- “这张图里的裤子，和商品白底图是同一个版型吗？”
- “具体是哪一个部位错了？左侧（模特右腿）的口袋是否多出来/缺失？”
- “修正后，人物、姿势、背景和其他正确部位有没有被一起改掉？”
- “这张图现在可以进详情页吗？如果不可以，下一步只需要改什么？”
- “这是已确认的问题、待人工确认的问题，还是模型尚未运行？”
- “这份 4K 文件是尺寸放大，还是确实补回了原图没有的细节？”

**[项目已验证事实]** 对外状态固定为 `PASS / CONDITIONAL_PASS / REWORK / REGENERATE / BLOCKED`；综合分不能覆盖 SKU、授权、安全和人工复验 Gate。

## 8. 看前后对比时的决策模型

**[未验证假设]** 用户看前后对比时最关心的不是“分数涨了多少”，而是以下三个可行动决定：

1. **采用修正版**：目标问题解决；商品结构与关键细节一致；人物/构图/非目标区域没有不可接受漂移；人工复验通过。
2. **继续返工**：目标问题部分解决，或出现新问题；用户能指出下一处具体缺陷，而不是只说分数低。
3. **放弃候选/重新生成**：主体、构图、授权或商品真值已不可恢复，继续修正的风险高于重新生成。

**[下一步真实问题]** 访谈中要求用户实际在 2–3 个脱敏对比案例上做选择，并解释选择；只问“你喜欢吗”不可证伪。

## 10. 今日产品决定分类

### keep

- **[项目已验证事实 → keep]** 保留“商品真值→候选→具体诊断→受控修正→前后人工复验→4K 交付”主链路。
- **[项目已验证事实 → keep]** 保留真实素材/示例隔离、Repair Case 版本链、人工终审、自动放行关闭和失败关闭。
- **[用户提供事实 + 未验证假设 → keep]** 把“具体问题、直接修正、前后提升”作为客户发现的核心价值假设。

### change now

- **[未验证假设 → change now]** 首屏和访谈演示以“最大问题 + 修正动作 + 前后图 + 下一步”组织，弱化独立评分。
- **[项目已验证事实 → change now]** 所有技术失败、未运行和不可评估状态继续用用户可理解语言显式显示，禁止用示例结果填空。
- **[未验证假设 → change now]** 每次修正强制记录用户选择的目标区域与“不变区域”，以支持非目标漂移复验。

### test next

- **[下一步真实问题 → test next]** 用 2–3 个真实、获授权的单 SKU 案例做人工访谈/任务测试，记录从上传到采用/返工/放弃的事件。
- **[下一步真实问题 → test next]** 对“可复述问题比例、目标解决率、漂移率、60 秒决策率、再次提交”做首轮基线；所有客户身份和素材按项目授权隔离。
- **[未验证假设 → test next]** 先比较服务交付与按批次报价的真实流程摩擦，不先实现计费系统。

### defer

- **[项目已验证事实 → defer]** 公开账户、复杂租户、全量云端项目列表、自动发布和自动放行。
- **[项目已验证事实 → defer]** 达人爬虫、营销扩展、多智能体自治集群及与核心修正无关的功能。
