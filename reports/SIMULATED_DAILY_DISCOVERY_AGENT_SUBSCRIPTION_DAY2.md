## 2. 目标企业与用户（模拟画像，不是客户结论）

### `[UNVERIFIED HYPOTHESIS]` 可能最在意的企业

1. **多角色协作的服饰品牌/店群内容团队**：运营提交商品目标，美工处理素材，视觉负责人终审。跨班次或跨天继续任务时，若商品事实、当前版本和修改边界丢失，疑似会回到群聊或表格。
2. **高频上新、同时维护多个 SKU 的代运营团队**：同一人可能在多个项目间切换，疑似最怕恢复到错误 SKU、旧版本或错误会话；重复点击导致多次生成/扣费也可能使其停止试用。
3. **受预算和审计约束的品牌团队**：疑似关心每次诊断/修正是否有可解释的额度记录、失败是否释放、谁批准了外部发送，而不只是“能不能聊天”。

### 用户、买方与阻断者

- `[UNVERIFIED HYPOTHESIS]` 主要用户：实际提交 SKU、描述问题、查看前后图并承担初审的商品运营或美工。
- `[UNVERIFIED HYPOTHESIS]` 关键决策者：对最终上架负责的视觉负责人/商品负责人；可能也是要求人工终审和版本追溯的人。
- `[UNVERIFIED HYPOTHESIS]` 购买/预算阻断者：品牌负责人、财务或采购；他们可能要求看到真实交付、明确消费记录和失败处理规则。

### `[SIMULATED RESPONSE]` 仅用于暴露待证伪假设

> “如果我关掉电脑后回来，系统还记得这件商品、我确认过的不能改区域和上一版，我才敢把任务交给它；但如果只是保存聊天，最后还是不能交付，我不会因为数据库买单。”

> “我最怕双击或网络卡顿后扣两次。你能显示一次请求、一次结果和失败退回，我才可能让同事一起用。”

这些不是受访者原话，不能计入采用、满意度或 WTP。

## 5. 最便宜的可证伪实验

`[PROPOSED / LOW-COST EXPERIMENT]` 不接支付、不运行收费模型、不应用生产数据库迁移。邀请 2–3 名真实参与服饰商品图返工/验收的人，各用一个获授权的脱敏真实 SKU；对照其现有“群聊/文件夹/PS/平台历史”流程，完成以下单次任务：

1. 记录 SKU 真值、目标区域、不变区域、参考图、当前版本和责任人。
2. 在本地受控原型中完成一次对话任务；中途主动关闭/刷新或换一个会话，再恢复到同一任务。
3. 对提交按钮做一次真实的快速重复点击或模拟网络等待；观察界面是否只产生一个可追溯请求，失败是否明确释放额度。此步骤只用 Mock/非收费路径，不把工程演示当生产承诺。
4. 让参与者在前后图中选择采用/继续返工/放弃，并要求指出恢复内容和扣费记录是否足以作决定。
5. 结束后回到其真实流程，记录是否愿意授权下一次真实小批次；不问“你愿不愿意付费”作为主要结果。

### 只记录能改变决策的事件

- 是否能在 60 秒内确认“这是正确 SKU、正确版本、正确会话”；
- 是否能恢复到上次人工确认的边界，而不是只恢复聊天文本；
- 重复点击/超时后是否产生多次任务、额度或人工补救；
- 是否做出有证据的采用/返工/放弃决定；
- 是否愿意提交下一次获授权真实批次，以及是否实际采用；
- 若有真实支出，记录凭证类型；不记录或不追问秘密金额。

### `[PROPOSED]` 证伪条件

若多数参与者在现有流程中已能低成本恢复，或不信任对话上下文；若重复点击保护对其无关紧要，因为他们从不让系统执行收费动作；若恢复后仍不能减少返工/沟通；或无人愿意授权下一批真实 SKU，则“可靠性能力会推动采用”暂不成立。此时优先验证交付服务和人工复验，不建设订阅扣费。

## 6. 最小反馈回路（不是当前数据）

`用户动作 → 事件 → 指标 → 预设阈值 → 产品决策`

| 事件 | 最小字段 | `[PROPOSED]` 指标与决策用途 |
|---|---|---|
| `task_resume_attempted` | 匿名批次、会话、SKU、上次状态、设备/会话变化 | 恢复成功率；低则先修上下文与错误提示 |

## 7. KEEP / CHANGE NOW / TEST NEXT / DEFER

### KEEP

- `[VERIFIED FACT → KEEP]` 保留“SKU 真值 → 对话目标 → 问题/边界确认 → 版本对比 → 人工终审”的核心闭环。
- `[VERIFIED FACT → KEEP]` 保留租户/项目/对话/商品/资产身份约束、父子版本链、失败关闭和重复动作幂等；这些是防止错 SKU、错版本和重复执行的安全基础。
- `[VERIFIED FACT → KEEP]` 保留额度 `AVAILABLE → HELD → CAPTURED / RELEASED` 的可解释状态；技术失败和 Gate 拦截不得捕获额度。
- `[VERIFIED FACT → KEEP]` 保留刷新恢复不等于重新授权：外部图片发送授权不跨刷新保留，避免历史同意扩大用途。

### CHANGE NOW

- `[VERIFIED FACT → CHANGE NOW]` 在恢复界面明确显示“商品、当前版本、上次确认边界、任务状态、最后更新时间和下一动作”；不要只展示可读聊天记录。
- `[PROPOSED → CHANGE NOW]` 将“已恢复”拆成“上下文已找回”和“外部执行仍需本次授权”；让用户能撤销错误恢复，避免恢复本身被理解为继续扣费。
- `[VERIFIED FACT → CHANGE NOW]` 在重复点击/超时场景显示同一请求 ID、处理中状态和最终额度变化；禁止用“按钮点了但不确定”迫使用户再次提交。
- `[VERIFIED FACT → CHANGE NOW]` 对数据库未配置、写入失败、版本冲突和额度结算异常显示可行动的失败关闭状态；不把本地浏览器成功包装成生产持久化。

### TEST NEXT

- `[NEXT REAL-WORLD VALIDATION QUESTION → TEST NEXT]` 以真实授权 SKU 做跨会话恢复对照，验证用户是否因恢复正确而减少重新沟通、重传和返工。
- `[NEXT REAL-WORLD VALIDATION QUESTION → TEST NEXT]` 观察一次真实或非收费受控重试中的行为：用户会等待、刷新还是重复点击；再验证幂等记录是否改变其下一次授权意愿。
- `[NEXT REAL-WORLD VALIDATION QUESTION → TEST NEXT]` 比较“按交付批次/人工服务”与“订阅积分”在真实预算流程中的可解释性；不先推断价格或收款意愿。

### DEFER

- `[VERIFIED FACT + NOT RUN → DEFER]` 公开支付、自动扣费、订阅自动续费、积分过期/转移、公开价格和收入预测。
- `[VERIFIED FACT + NOT RUN → DEFER]` 在真实数据库迁移、认证/租户隔离、授权审计和恢复演练未完成前，宣称“生产级跨会话恢复”或允许真实收费调用。
- `[UNVERIFIED HYPOTHESIS → DEFER]` 把“恢复成功次数”“幂等请求数”直接当客户价值或订阅计费单位；它们首先是可靠性与安全指标。
- `[UNVERIFIED HYPOTHESIS → DEFER]` 扩大到多品类、自动发布、自动放行、达人或营销功能；本轮只验证单 SKU 返工采用。

## 8. 模拟结论与下一步

`[SIMULATED / NOT CUSTOMER EVIDENCE]` 数据库持久化、跨会话恢复和重复点击不扣费，最可能影响的是“敢不敢把任务交给系统、敢不敢让同事接手、出了异常是否继续使用”，而不是单独创造服饰电商的核心价值。核心价值仍需由真实 SKU 的可采用结果、减少返工/沟通和实际采用证明。

`[NOT RUN]` 当前没有证据证明任何企业最痛、恢复功能减少了真实成本、幂等保护提高了采用、订阅积分适配预算、客户付款或复购。

`[NEXT REAL-WORLD VALIDATION QUESTION]` 下一轮只需回答一个可行动问题：一个真实参与返工的人，在跨会话恢复和一次重复点击异常后，是否愿意授权下一批真实 SKU，并最终采用其中的修正版？若不能，先修交付与人工复验闭环，不升级订阅商业判断。
